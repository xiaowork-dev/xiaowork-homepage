# P6-B 安全与功能测试记录

> 检查日期：2026-10-26。本记录按用户提出的 15 项验收要求组织，记录已经执行的测试及其边界。P6-B 是本地管理 API 阶段，不表示管理界面、发布 worker、备份恢复或生产安全验收已经完成。

## 环境、证据与结果口径

本机 Go 测试使用 Go 1.27.3、SQLite 3.54.1，真实启动 HTTPS 测试服务器。HTTP 用例通过 TLS 客户端、登录 challenge、Secure Cookie、会话 CSRF 和实际 SQLite 执行，没有用直接调用未鉴权 handler 代替认证 HTTP 验证。测试证书仅由该本地测试服务器的客户端信任，没有关闭 TLS 校验，也不涉及生产域名或服务器。

主要证据：

- **E1：全包本机测试基线**：本地 `.cache/p6b-go-tests.txt`。authn、contentdata、devtls、httpapi、mediautils、store 均有实际 PASS 输出；SQLite `integrity=ok`。该日志早于媒体查询参数和上传期间版本变化的最后补充回归，不能将其当作最终文件版本的完整复跑记录。
- **E2：已保存的认证 HTTP 证据**：[P6B-auth-http.txt](evidence/P6B-auth-http.txt)。包含请求方法、资源路径、预期及实际状态码，以及认证/服务安全测试结果；不包含真实密码、Cookie、会话 token 或服务秘密。
- **E3：本轮媒体补充实测**：实际运行 `go test ./internal/mediautils ./internal/httpapi -run 'TestSanitize|TestMedia' -count=1 -v` 通过；媒体接口最终又执行 `go test ./internal/httpapi -run TestMediaHTTPSLifecycleAndRejectedUploads -count=1 -v` 通过。后者覆盖非法转义、未知与重复 query。测试源码见 [media_http_test.go](../backend/internal/httpapi/media_http_test.go)、[media_storage_test.go](../backend/internal/httpapi/media_storage_test.go)、[image_test.go](../backend/internal/mediautils/image_test.go)。这些局部执行结果来自本轮实际工具输出，最终完整 Linux 复跑已归档为 [P6B-go-tests.txt](evidence/P6B-go-tests.txt)。
- **E4：依赖审计**：[npm 审计](evidence/P6B-npm-audit.json)、[Go 扫描](evidence/P6B-govulncheck.txt)，另保留本地 `.cache/p6b-govulncheck-verbose.txt`。结果见本文“依赖风险”部分。

- **E6：最终 Linux 全包复验**：初轮 Linux 全包测试实际发现 fixture 上传根目录权限过宽，媒体 HTTPS 请求在读取 multipart 前返回 500。Go 1.27.3 的 `testing.TempDir()` leaf 以 0777/umask 创建；fixture 已改为显式 0700 的独立 `uploads` 子目录，生产检查保持严格。随后在已有 `xiaowork-homepage-api:p6b-test` 镜像中仅只读挂载修正的 `auth_test.go`，隔离执行 `go test ./internal/httpapi -run TestMedia -count=1 -v` 实际全 PASS（2.290s），包含并发及 Linux symlink 分支。修正后从最终源码重建测试镜像，在 network=none 的独立 Linux 容器完整执行 `go test -count=1 -v ./...` 和 `go vet ./...`，48 个顶层测试通过、0 fail、0 skip；日志含 224 条实际 HTTP 预期/结果记录，见 [最终 Go 证据](evidence/P6B-go-tests.txt)。

`.cache/` 是本地忽略目录，其中的运行数据库、私有媒体、Cookie、会话文件和 TLS 私钥不得提交。公开交付只保留已脱敏的必要测试结果。本文件不复制私有会话文件内容。

## 依赖风险：未将未修复问题标记为已修复

### npm

本轮实际 `npm audit` 仍为 **7 high、0 critical**；这是一个根 advisory 沿依赖链产生的 7 个受影响依赖记录，不能写成 7 个不同根漏洞，也不能写成审计清零。

受影响链包含 Nuxt/Nitro 构建工具中的 `listhen → node-forge@1.4.0`。根问题是 **GHSA-86w9-cpqp-85rv**，node-forge RSA PKCS#1 v1.5 签名校验可接受额外嵌套 DigestAlgorithm，审计范围为 `<=1.4.0`。本轮 `npm view` 核对的最新 node-forge 仍为 1.4.0，尚无本轮确认可采用的兼容修复。audit 提议转用 Nuxt 4.1.3，被标记为不兼容变化；未运行强制修复、降级或未审查的 override。

当前访客静态生产镜像由 Nginx 服务静态文件，不携带 Node/npm 运行时；新增 Go API 也不运行 node-forge。此边界降低当前运行时暴露，但**没有修复构建依赖漏洞**。本地开发、CI 及未来发布 worker 的构建环境仍须隔离、不处理不可信证书/签名输入、限制网络与挂载，并继续复查上游。既有未经用户接受的 high 风险发布门槛继续有效；不能因 P6-B 测试通过而视为用户接受。

### Go

实际使用 govulncheck 1.9.0 扫描项目后，结果为 **symbol 0、imported package 0、required module 1**。模块记录为 **GO-2026-5932**：`golang.org/x/crypto/openpgp` 已停止维护、设计存在安全问题，扫描显示无修复版本。

本项目锁定 `golang.org/x/crypto@v0.58.0`，仅使用所需的 Argon2 密码组件，没有导入 openpgp；本轮扫描没有发现项目调用受影响符号或导入受影响包。该模块级记录仍保留，不能描述成整个 x/crypto 模块已无风险或已修复。后续新增依赖或导入路径后须重新扫描，不允许因为本轮 symbol=0 就忽略未来可达性变化。

## 尚待补充的验证与限制

- Docker 重建持久化已实测通过第 13 项；备份恢复、跨主机迁移和卷损坏恢复不属于此结论。
- Linux 初轮全包测试暴露的 fixture 目录权限问题已修正；最终全包 48 项通过，POSIX 文件/目录权限、首次宽权限拒绝与 symlink 分支均执行，没有跳过。
- 时间限制测试使用受控服务端时钟，没有等待真实 30 分钟/12 小时。idle 和持续成功交互下的绝对期限已有独立 HTTPS 断言；独立绝对期限用例已包含在最终 Linux 全包日志。
- 图片解码并发与限长实际执行；没有据此宣称完成恶意图片全集、真实 GPS 资料清除验证、容器内最大尺寸峰值资源校准或 DoS 压测。
