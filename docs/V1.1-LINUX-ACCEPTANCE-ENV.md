## 排查完成后使用的计划命令（本轮不再执行）

安装授权已具备，但服务崩溃尚未解决。确认可以安全继续后，先在 PowerShell 重新检查发行版、资源及安装选项，确认 C 盘目标尚不存在；出现残留目录或注册项时停止，不覆盖或注销：

```powershell
wsl --list --verbose
wsl --list --online
wsl --help
wsl --install --distribution Ubuntu-24.04 --location C:\WSL\XiaoWork-P6E --no-launch --version 2
wsl --distribution Ubuntu-24.04
```

只初始化这个新发行版的普通用户。不要执行 `wsl --shutdown`，不要停止、注销或重装 `docker-desktop`。Windows 的 Docker 默认 context 不变。安装可能影响 WSL 默认发行版；后续命令始终显式指定 `--distribution`，任何默认值调整先核对影响。

在 Docker Desktop 设置中仅关闭**新 Ubuntu 发行版**的 WSL Integration，保留已有设置。之后在新 Ubuntu 内安装独立 Engine。不得用 Desktop 注入的 CLI/socket 冒充原生 Engine。

```bash
sudo apt-get update
sudo apt-get install ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
gpg --show-keys --with-fingerprint /etc/apt/keyrings/docker.asc
. /etc/os-release
printf 'Types: deb\nURIs: https://download.docker.com/linux/ubuntu\nSuites: %s\nComponents: stable\nSigned-By: /etc/apt/keyrings/docker.asc\n' "$VERSION_CODENAME" | sudo tee /etc/apt/sources.list.d/docker.sources
sudo apt-get update
apt-cache policy docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

核对官方签名指纹与候选软件版本后，按实查版本安装并记录完整版本号，不使用 `curl | sh`，不关闭 TLS 校验。安装前检查 `systemctl is-system-running`；若需要为**新发行版**启用 systemd，应先保存 `/etc/wsl.conf`，只追加经确认的 `[boot] systemd=true`，从 Windows 仅终止并重启该新发行版。不能改 Desktop 的服务或全局 `.wslconfig`。

```bash
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo systemctl status docker --no-pager
```

将测试用户加入 `docker` 组等同于赋予该 **Linux 测试环境**的 root 控制能力；是否采用由用户确认。也可以明确使用 `sudo` 运行本项目 Docker 工具。不要修改当前 Windows Docker 权限。

## 证明是真正独立的 Daemon

```bash
env -u DOCKER_CONTEXT -u DOCKER_TLS_VERIFY DOCKER_HOST=unix:///var/run/docker.sock docker info
systemctl show docker -p MainPID -p ExecStart
pgrep -a dockerd
readlink -f /var/run/docker.sock
findmnt -T /var/lib/docker
findmnt -T "$HOME"
```

必须同时证明：发行版内有本地 `dockerd` 进程、systemd 服务对应该进程；Unix socket 不指向 `/mnt/wsl/docker-desktop` 或 Desktop 的共享 socket；Daemon ID 与上述 Desktop ID 不同；操作系统不是 `Docker Desktop`；源码、备份及 Docker 数据实际落在 Linux 文件系统（例如 ext4），不是 `/mnt/c`、`/mnt/d`、DrvFs、9p 或 Desktop 的 Windows bind 映射。CLI 所在位置、一个 context 名或单一字符串都不能作为身份证明。

后续命令使用显式 `DOCKER_HOST=unix:///var/run/docker.sock`，不运行 `docker context use`。保存 daemon、进程、socket inode、mountinfo、实际 bind Source、realpath/符号链接检查和完整命令到新机器证据。

## 清理及影响

安装会增加独立发行版 VHDX、Linux Engine 服务及磁盘占用；WSL 内核/内存资源仍与 Desktop 共享。不要同时进行两套高负载构建。没有理由更改现有 Docker context、Desktop Daemon、现有业务端口或生产配置。

验收后默认保留故障现场与证据。只有另获授权并导出证据、加密备份且确认恢复可行后，才停新发行版的 Docker 服务、按**准确项目标签**清理其测试容器。卷及未知锁不自动删除。最后可在 Windows 对确切新发行版执行 `wsl --export`；`wsl --unregister Ubuntu-24.04` 会删除整套 Linux 数据，属于另行确认的破坏性步骤，**本方案不自动执行**。不使用 Docker 全局 prune。
