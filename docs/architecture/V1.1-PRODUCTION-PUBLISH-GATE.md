# V1.1 生产发布 gate 设计

- 日期：2026-11-08（Asia/Shanghai）
- 状态：**设计稿，待用户确认决策项后实现**。本文不改变任何运行代码；正式发布 gate 继续硬关闭。
- 关联：[发布与失败恢复设计](V1.1-PUBLISHING.md)、[部署与更新](../V1.1-RELEASE-OPERATIONS.md)、[备份恢复](../V1.1-BACKUP-RESTORE.md)

## 1. 现状

发布链路本身与环境无关，已实现并经过隔离验收：

```
草稿 → 冻结快照 → 无网络 Worker 固定构建 → 产物校验 → prepared/intent
     → current 原子切换 → receipt → API 经内网 publication-static 逐文件对账 → succeeded / recovery_required
```

生产拓扑（`openresty`）缺的只是**授权**，目前被三处硬开关挡住：

| 位置                                                                     | 现有限制                                                           |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| `backend/internal/httpapi/publication.go` 的 `validatePublicationConfig` | `LocalPublish` 只允许 localhost origin                             |
| `scripts/v11-release.mjs` 的 `configuration()`                           | `openresty` 拓扑断言 `Production publishing remains hard-disabled` |
| Compose `worker` 服务                                                    | 在 `publisher` profile 下，生产拓扑默认不启动                      |

在生产环境开放发布后会多出这些风险：

1. 被盗的管理员会话可以篡改全站公开内容。
2. 发布了未经独立验收的镜像组（例如更新后忘了复验）。
3. 在没有可用备份时出现不可恢复的错误。
4. 需要立即停止发布时，没有不依赖 Web 的关闭手段。
5. 生产发布与日常维护、更新互相竞争。

## 2. 设计原则

1. **不新增第二套发布代码路径**。生产和本地验收使用同一套快照、构建、校验、切换、对账代码，只在授权层区分。
2. **开关只在宿主上，Web 不能自行开启**。授权记录写在只有离线运维工具可写的控制卷里，API 和 Worker 只读挂载。
3. **授权绑定具体发行身份**。授权记录写明完整源码 SHA、Worker 镜像 ID、schema 和项目名；更新或回退镜像后授权自动失效，必须重新验收、重新授权。
4. **失败即关闭**。授权文件缺失、无法解析、身份不符、已撤销或已过期时，一律拒绝新任务；已在进行中的任务只允许按现有协议完成或进入恢复对账，不会被中途强杀成未知状态。
5. **每次发布都要人在场**。保留现有的重新输入密码（5 分钟窗口）、"确认更新整个站点"和 `reviewedActiveReleaseId` 校验，并在生产环境额外要求先预览、再发布。

## 3. 总体结构

```
宿主操作员（SSH，root）
  └─ node scripts/v11-release.mjs authorize-publishing --project P --approval-note "…"
       ├─ 前置检查：current 描述符、屏障 ready、24 小时内有已验证的备份、存储非 critical
       ├─ 维护镜像 homepage-control 写入控制卷：publish-authorization.json（原子写入、fsync、0600、UID 10001）
       └─ 以 --profile publisher 启动 Worker（不重建 API）

控制卷（API/Worker 只读挂载）
  ├─ state.json                    （现有维护屏障）
  ├─ publish-authorization.json    （新增：授权记录）
  └─ publish-revoked.json          （新增：撤销记录，存在即拒绝）

API（每次创建任务、Worker 领取任务时读取并校验授权）   Worker（领取任务时由 API 判定）
```

### 3.1 授权记录格式

```json
{
  "format": 1,
  "project": "xiaowork-homepage-v11-prod",
  "origin": "https://xiaoworks.com",
  "source": "<40 位完整 SHA>",
  "schema": 3,
  "workerImage": "sha256:<64>",
  "apiImage": "sha256:<64>",
  "issuedAt": "2026-…Z",
  "expiresAt": "2026-…Z",
  "backup": { "path": "<宿主备份目录>", "contentManifestSHA256": "<64>", "verifiedAt": "2026-…Z" },
  "approvalNote": "非机密的批准说明（谁、为何、对应哪份验收报告）",
  "id": "<UUID>"
}
```

API 校验规则（与维护屏障一样，用目录描述符安全打开，拒绝符号链接、硬链接、group/other 权限和超大文件）：

- `origin` 必须等于 API 的 `XIAOWORK_ORIGIN`（固定为 `https://xiaoworks.com`）；
- `source`、`workerImage` 分别等于 API 自身的 `XIAOWORK_SOURCE_REVISION` 和 `XIAOWORK_BUILDER_ID`；
- `schema` 等于 `store.SchemaVersion`；
- 当前时间位于 `issuedAt` 与 `expiresAt` 之间；
- 不存在 `publish-revoked.json`。

任何一项不满足，`publishing-status` 就返回 `enabled:false` 和具体的中文原因；创建任务返回 503 `PUBLISH_GATE_CLOSED`。

### 3.2 运行配置

- 用 `XIAOWORK_PUBLISH_MODE=off|local|production` 取代布尔值 `XIAOWORK_LOCAL_PUBLISH`：
  - `local` 维持现状，只允许 localhost origin；
  - `production` 只允许 `https://xiaoworks.com`，**并且**必须有有效的授权记录；
  - 两种模式互斥，不会出现"本地开关在生产生效"。
- `v11-release.mjs` 的 `openresty` 拓扑默认是 `off`。只有 `authorize-publishing` 命令能把它切到 `production` 并启动 Worker；`deploy` 和 `update` 不会顺带开启。
- `update` 和 `rollback` 成功后，因为镜像 ID 已经变化，旧授权会自动失效，工具会提示需要重新验收并授权。

### 3.3 运维命令

| 命令                                                              | 作用                                          | 前置检查                                                                                                                              |
| ----------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `authorize-publishing --project P --approval-note "…" [--days N]` | 写入授权记录并启动 Worker                     | 屏障 ready；没有锁或 recovery 标记；N 天内（默认 1 天）有工具验证过的备份；存储非 critical；HTTP 探测通过；描述符与正在运行的镜像一致 |
| `revoke-publishing --project P --reason "…"`                      | 写入撤销记录（**立即生效**），然后停止 Worker | 无（随时可用，紧急关闭）                                                                                                              |
| `publishing-status --project P`                                   | 只读显示授权、撤销、到期时间和最近一次备份    | 无                                                                                                                                    |

撤销后，进行中的任务仍可以完成 prepared 之后的切换和对账，或者进入 `recovery_required`；新任务、新领取一律拒绝。重新开启必须再执行一次 `authorize-publishing`，生成新的 `id`。

### 3.4 生产环境的单次发布规则

在现有的密码重新验证、`confirmAllChanges` 和 `reviewedActiveReleaseId` 之上增加：

1. **先预览后发布**：发布请求必须引用同一工作区修订号、24 小时内成功的预览快照，否则返回 422 `PREVIEW_REQUIRED`。恢复历史版本（rollback）不需要预览，因为目标是已经验证过的历史发布。
2. **频率上限**：每小时最多 6 个发布或恢复任务，超出返回 429。这既防止被盗会话反复篡改，也限制构建资源占用。
3. **审计**：授权、撤销、每个任务的排队、成功、失败和恢复都写入 `audit_events`，并记录授权 `id`。

### 3.5 与现有机制的关系

- **维护屏障**：发布任务已经持有共享租约，备份、更新时会先排空任务；授权命令自身会进入并完成屏障，不与维护竞争。
- **备份**：授权要求有新备份，只是一道门槛，**不能替代**定时异地备份（异地备份仍是独立待办）。
- **Cloudflare**：根域名目前是仅 DNS（灰云），没有 CDN 缓存一致性问题。以后开启橙云时，必须让 HTML、`/admin`、`/api` 绕过缓存，并先完成 OpenResty 的 real_ip 配置，然后才能保持授权有效。
- **真实客户端地址**：B6 修复后限速按真实访客计算，被盗会话之外的匿名攻击无法通过锁死登录来阻止管理员发起紧急恢复。

## 4. 威胁与对策

| 威胁                            | 对策                                                                                                                        | 残余风险                                                                 |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 被盗会话 Cookie 发布篡改内容    | `__Host-`/HttpOnly/SameSite=Strict；发布前 5 分钟内必须重新输入密码；先预览；频率上限；后台一键恢复历史版本；宿主可随时撤销 | 攻击者同时掌握密码时仍能发布。可选增加 TOTP（见决策 D3）                 |
| 发布了未验收的镜像              | 授权绑定 SHA 和镜像 ID，更新后自动失效                                                                                      | 操作员仍可能为未验收组授权：命令会要求填写批准说明，并显示验收报告路径   |
| Web 或 API 被攻破后自行开启发布 | 控制卷对 API/Worker 只读，授权只能由维护镜像写入                                                                            | API 进程被完全控制时，在授权有效期内仍可发布；到期和撤销可以限制持续时间 |
| 发布失败无法恢复                | 现有原子切换、对账、恢复；授权前要求有新备份                                                                                | 机器或磁盘整体故障需要依赖异地备份（待落地）                             |
| 需要紧急停止                    | `revoke-publishing` 不依赖 Web，立即生效                                                                                    | 进行中的任务会按协议完成或进入恢复，不会立刻中断                         |

## 5. 需要用户确认的决策

| 编号 | 决策                           | 推荐                                                | 备选                                      |
| ---- | ------------------------------ | --------------------------------------------------- | ----------------------------------------- |
| D1   | 生产首批开放范围               | **预览 + 发布 + 恢复全部开放**                      | 先只开放预览，发布另行授权                |
| D2   | 生产环境是否要求"先预览后发布" | **要求**（24 小时内、同一修订号）                   | 不要求                                    |
| D3   | 发布的第二因素                 | **首版只用密码重新验证**（现有机制），TOTP 另行排期 | 首版就实现 TOTP（会增加初始化和恢复流程） |
| D4   | 授权有效期                     | **默认 7 天**，到期后需重新授权；更新镜像后立即失效 | 不设时限，只按镜像身份失效                |
| D5   | 授权所需备份的新鲜度           | **24 小时内由工具验证过的备份**                     | 7 天内                                    |
| D6   | 频率上限                       | **每小时 6 个发布或恢复任务**                       | 其他数值                                  |

## 6. 实现与验收计划（确认决策后执行）

**代码**（在功能分支上提交，每项都配测试）：

1. `backend/internal/publishgate`：授权和撤销记录的安全读取与校验（Linux 目录描述符、权限、大小、格式、身份、时间窗口）；Go 单元测试覆盖每种拒绝原因。
2. `homepage-control`：新增 `authorize-publish`、`revoke-publish` 子命令（原子写入、fsync、排他创建，不覆盖旧记录）。
3. `httpapi`：引入 `PublishMode`；创建任务和 Worker 领取任务时校验授权；`publishing-status` 显示原因；先预览规则；频率上限；审计。
4. `v11-release.mjs`：新增 `authorize-publishing`、`revoke-publishing`、`publishing-status` 命令；`openresty` 拓扑默认 `off`；`update`/`rollback` 后提示授权已失效。
5. 后台 UI：发布页显示授权状态、到期时间和"需要先预览"的提示。

**隔离验收**（主服务器独立测试目录，生产拓扑，只绑回环）：

- 未授权时预览、发布、恢复都被拒绝；授权后完成预览 → 发布 A → 发布 B → 恢复 A，公开字节一致；
- 未预览直接发布被拒；超过频率上限被拒；
- 撤销后新任务立即被拒，进行中的任务正常完成或进入恢复；
- 授权到期后被拒；镜像身份不符（`update` 之后）时授权自动失效；
- 没有新备份时拒绝授权；
- 控制卷对 API/Worker 确认为只读，Web 无法写入授权；
- 其他业务不受影响。

**正式启用**：完成上述验收，并经用户另行批准正式切换和首次发布之后，才在正式项目执行 `authorize-publishing`。
