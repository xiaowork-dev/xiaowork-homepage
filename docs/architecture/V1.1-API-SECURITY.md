# XiaoWork Homepage V1.1：管理 API 与安全契约

> 阶段：P6-A 方案设计，2026-10-26。本文是后续实现与验收约束，不表示认证、上传、发布 worker 或管理页面已经实现。
> 本阶段只建立独立本地骨架，不变更生产容器、OpenResty、DNS、证书或公网发布门槛；本轮生产版本的只读核对结果见阶段交付，不将只读核对写成部署变更。

## 1. 范围与信任边界

正式公开站 origin 固定为 `https://xiaoworks.com`，不增加 www。公开站继续采用 Nuxt 静态生成，保留已确认的三页、视觉、响应式、主题及项目真实性边界。

管理界面计划放在独立 `admin/` 目录，使用 Vue 3、TypeScript 与 Vite，构建为 `/admin/` 下的独立资源；不使用 Nuxt layer，不把管理路由、认证代码或私有数据导入访客 bundle。P6-C 再添加管理端构建配置与所需直接依赖，复用兼容的根 Vue/TypeScript 版本；不能因为 Nuxt 已间接安装 Vite，就依赖未声明且未锁定的传递版本。

管理 API 前缀为 `/api/admin/v1`，由独立 Go 服务提供，SQLite 保存账户、会话、工作区、不可变公开快照、任务和审计记录。它不成为访客页面的运行依赖。SQLite、上传原件、草稿与 staging 均不在公开静态根目录。

| 组件             | 允许能力                                                                | 禁止能力                                                         |
| ---------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 静态 Nginx       | 只读当前公开页面、保留的版本资源及公开媒体                              | 读取 SQLite、私有媒体、管理配置；写发布目录                      |
| Go API           | 写私有 SQLite/媒体；认证；提交任务；只读核验发布结果                    | 执行 shell、任意进程、Git/Docker/SSH；写发布根或切 current       |
| 固定 Node worker | 经私有 UDS 领取任务；读取指定快照与媒体；构建、验证、写发布根并原子切换 | 挂载 SQLite、Docker socket、SSH 密钥；接受任意命令/路径/构建参数 |
| 管理浏览器       | 经同源认证 API 管理内容、查看受保护预览与任务                           | 接触数据库、构建凭据；直接调用 worker 或提交可执行配置           |

未来 API 与 worker 使用独立容器，均为专用非 root UID `10001`；共享 UID 只解决 `0600` UDS 的拨入权限，**不构成不同 UID 的进程隔离**。权限隔离依靠不同容器与明确的挂载清单：API 无发布根写挂载，worker 无数据库挂载。宿主仍需隔离其他同 UID 进程，不能把 socket 卷分发给无关容器。

API 可以只读挂载发布根，以核对 `current`、版本 manifest 与 receipt；该挂载不产生 HTTP 静态目录映射。预览使用单独的只读挂载与显式认证路由，不能把 staging 或发布根整体交给文件服务器。

现有 npm high 风险、生产发布限制与 P5 记录继续有效。新管理架构不等于这些风险已修复或用户已接受。

## 2. 通用 HTTP 契约

### 2.1 请求与响应

- 仅接受已登记的路径、方法与 `Content-Type`。JSON 写操作必须为 `application/json`；上传另用 multipart。
- JSON 拒绝未知字段、重复键、尾随第二个 JSON 值、非法 UTF-8；不执行 JavaScript、不解释模板、SQL 或 shell 表达式。
- ID 为服务端生成的不可猜随机标识；客户端只能引用已有 ID。发布 ID、媒体 ID 不是认证凭据。
- HTTP时间统一 RFC 3339 UTC；SQLite内部使用可信服务生成的UTC Unix秒，序列化时显式转换。排序使用显式整数，不编造项目发布日期。
- 普通 JSON 请求体上限 256 KiB；登录/改密 8 KiB；上传限额见第 7 节。分页 `limit` 默认 20、最大 100，游标为不透明字符串。
- 不接受任意重定向地址、文件系统路径、远端下载 URL、shell 参数或 Git ref。接口不提供通用代理、远程截图、插件安装或代码编辑。
- 所有管理 HTML、API JSON、认证媒体、预览与错误响应使用 `Cache-Control: no-store`；不由 CDN 缓存。返回 `X-Content-Type-Options: nosniff`。
- API 不启用跨域凭据访问，不返回通配 CORS 头。生产只接受固定主站 origin；开发使用独立、显式允许的本地 HTTPS origin，不扩展成任意子域或任意 localhost 端口。

成功响应结构示例（省略项目其余响应字段，不是完整可提交项目）：

```json
{
  "data": {
    "revision": "ws-42",
    "project": {
      "id": "prj_7dca8f4e56b347ca92b1e6d510ef0cba",
      "slug": "blog",
      "name": "XiaoWork Blog"
    }
  },
  "requestId": "req_81f934b2"
}
```

错误响应使用统一结构，不包含 SQL、堆栈、绝对路径、密码、Cookie、会话/CSRF token 或原始上传内容：

```json
{
  "error": {
    "code": "REVISION_CONFLICT",
    "message": "内容已被其他操作更新，请刷新后重试。",
    "fields": [],
    "currentRevision": "ws-43"
  },
  "requestId": "req_b5032c01"
}
```

`fields` 只返回允许公开给管理员的字段名与错误码，不回显敏感值。`requestId` 为服务端生成的诊断标识，不能直接信任客户端同名头。

| HTTP 状态 | 错误码示例                                                              | 含义                                    |
| --------- | ----------------------------------------------------------------------- | --------------------------------------- |
| 400       | `INVALID_REQUEST`、`UNKNOWN_FIELD`                                      | JSON、参数或请求结构错误                |
| 401       | `AUTH_REQUIRED`、`INVALID_CREDENTIALS`                                  | 未登录/过期，或统一的用户名密码错误     |
| 403       | `ORIGIN_REJECTED`、`CSRF_REJECTED`、`REAUTH_REQUIRED`                   | 来源、CSRF 或敏感操作再认证不满足       |
| 404       | `NOT_FOUND`                                                             | 未登记路径或当前账户不可见的对象        |
| 405       | `METHOD_NOT_ALLOWED`                                                    | 已登记资源不支持该方法，返回固定 Allow  |
| 409       | `REVISION_CONFLICT`、`JOB_CONFLICT`、`MEDIA_REFERENCED`                 | 工作区冲突、发布互斥或媒体仍被引用      |
| 413       | `BODY_TOO_LARGE`、`IMAGE_TOO_LARGE`                                     | 请求体、尺寸或像素超限                  |
| 415       | `UNSUPPORTED_MEDIA_TYPE`                                                | 非允许的 MIME/真实图片格式              |
| 422       | `VALIDATION_FAILED`                                                     | 已解析内容不符合字段或发布规则          |
| 428       | `REVISION_REQUIRED`                                                     | 缺少工作区 If-Match                     |
| 429       | `RATE_LIMITED`、`AUTH_CAPACITY`                                         | 限速或密码验证资源已满，附 Retry-After  |
| 503       | `SETUP_REQUIRED`、`WORKER_UNAVAILABLE`、`STATE_RECONCILIATION_REQUIRED` | 未初始化、worker 不可用或发布状态待核对 |

本项目按约定将工作区版本不匹配返回 `409 REVISION_CONFLICT`；不得由代理改写为成功或自动覆盖。数据库/磁盘内部错误返回通用 `500 INTERNAL_ERROR`，详情只写脱敏服务日志。

### 2.2 工作区版本与幂等

`GET /workspace` 返回完整草稿公开字段、`revision` 及 `ETag: "ws-42"`。项目、简介、设置、媒体引用和排序的写请求必须携带相同格式的 `If-Match: "ws-42"`。

服务端在一个 SQLite 事务内比较当前版本、完成校验、写入变更、递增版本并追加审计。缺头返回 428，版本落后返回 409；不接受弱ETag、通配符或多个If-Match值，格式错误返回400。绝不自动合并或最后写入覆盖。SQL使用参数绑定，开启适用的外键约束，迁移不得在API请求里执行。管理端保留用户未提交表单，提供刷新/重新应用的显式操作。

创建项目、提交预览/发布/回滚任务使用 `Idempotency-Key`，长度 16～128，仅允许字母数字和 `-_`。作用域为账户、端点及规范化请求哈希；同键同请求返回原对象，同键不同请求返回 409。记录至少保留 24 小时。客户端重试不能重复创建发布任务。

认证、读取任务等无工作区写入的操作不要求 If-Match。发布/预览任务锁定提交时的工作区 revision 并创建不可变快照；后续编辑不改变已排队任务。

## 3. 账户初始化、密码与会话

### 3.1 初始化与改密

首版仅一个管理员，不提供公开注册、邀请、找回密码邮件或远程初始化接口。固定 CLI 命令在服务器本地 TTY 交互读取账户名与两次密码；拒绝非 TTY、命令行密码参数、环境变量密码、标准输入管道及默认密码。CLI 不打印密码或完整哈希，也不把它们写入 shell 历史/日志。

初始化在事务和排他保护下只允许账户不存在时执行；已有账户时拒绝覆盖。离线重置仍需本地受控 TTY 操作，并撤销该账户全部会话、登录 nonce 与再认证状态；不能生成隐蔽的备用账户。CLI/数据库文件权限与备份方式由后续部署文档明确，不向 Git 提交真实数据库。

密码按原始 UTF-8 字节处理，不自动 trim、大小写转换或 Unicode 规范化。长度 12～128 个 Unicode 码点且 UTF-8 不超过 1,024 字节；只做长度约束，不强加可预测的字符组合规则。

密码采用 Argon2id：内存 `64 MiB`（参数为 `65536 KiB`）、迭代 `t=3`、并行度 `p=1`、密码学随机 salt `16 bytes`、输出 `32 bytes`。存储含算法版本与参数的可升级编码，不存明文或可逆密码。参数由固定服务配置控制，不能由登录 JSON 指定；成功登录时可按未来批准的更强策略重哈希，不擅自降低成本。

密码变更要求有效会话、CSRF、当前密码和两次相同新密码；提交后撤销全部会话，包括当前会话，清除 Cookie并要求重新登录。错误不区分账户不存在、密码错误或账户名大小写是否匹配。

### 3.2 会话

登录成功生成密码学随机 `32 bytes` 的不透明会话 token，使用无填充 base64url 传入 Cookie。SQLite 只保存其 SHA-256 哈希和必要会话元数据，不保存原 token、可逆副本或可用于直接登录的日志值；该高熵 token 的查找哈希不使用密码 KDF。

生产 Cookie 固定约束：

```text
__Host-xiaowork-admin=<opaque-token>; Secure; HttpOnly; SameSite=Strict; Path=/
```

不设置 Domain，不把 token 放在 localStorage、sessionStorage、URL、响应 JSON 或前端可读 Cookie。由于 `__Host-` Cookie要求 Path=/，浏览器可能随公开页请求发送 Cookie；静态访问日志、CDN规则与代理不得记录或回显它。生产及本地验证均使用满足 Secure 的 HTTPS，不自动降级成非安全 Cookie。

会话空闲有效期 30 分钟，绝对有效期 12 小时，以服务端时间为准；Cookie 的最长寿命不超过绝对有效期。仅有效已认证请求更新活动时间，且合并写入频率；后台轮询不应无限延长无人操作的会话。服务端记录 `lastInteractiveAt`，任务轮询/心跳不刷新它，过期后统一返回401。

注销撤销当前会话并删除相同属性的 Cookie。改密、CLI重置、账户禁用或认证策略升级撤销全部会话。登录不复用预登录会话ID，防止会话固定。服务重启后根据数据库中哈希/时间校验，不将已有 Cookie 无条件视为有效。

### 3.3 登录 nonce、CSRF 与来源

`GET /auth/login-challenge` 生成一次性随机登录 nonce，响应 `loginNonce` 和有效期，同时设置独立的 Secure、HttpOnly、SameSite=Strict、Path=/ 的 `__Host-xiaowork-login` 预登录 Cookie。数据库只保存预登录 Cookie和 nonce 的哈希关联；5分钟过期，单来源最多10个、全局最多1,000个未使用记录，过期记录有界清理。

`POST /auth/login` 同时要求预登录 Cookie、`X-CSRF-Token: <loginNonce>`、精确匹配的 Origin 与 JSON 内容。nonce 在一次验证尝试前原子消费，无论密码对错都不能重用；随后若需重试应申请新 challenge。登录成功清理预登录 Cookie。

已登录会话的CSRF token使用服务端秘密密钥派生：`base64url(HMAC-SHA256(K_version, "xiaowork-admin-csrf-v1\0" || 原始32字节会话token))`。域分隔字节与编码规则固定，不能由客户端指定；服务端从HttpOnly会话Cookie取得原token后可重复派生，所以`GET /auth/session`能返回相同CSRF，不因刷新或多标签页读取而使其他标签页失效。

数据库只存会话token哈希与CSRF token哈希，不存原token；当前keyVersion记录在受控服务配置中。登录响应及`GET /auth/session`仅向同源已认证前端返回派生CSRF，并校验其哈希与该会话已登记哈希一致。写请求先验证有效会话，再以恒定时间比较提交CSRF的哈希和该会话已登记哈希，并核对服务端派生结果。CSRF不是登录凭据，不替代Cookie，也不写URL或日志。

`K_version`至少32字节密码学随机值，放在服务端专用`0600`秘密文件，不进入SQLite、前端、`VITE_*`变量、Git或公开日志。keyVersion来自服务配置而不是请求；首版轮换在维护流程中明确撤销全部旧会话，再原子替换secret/配置，不保留跨密钥版本会话，不能悄悄生成新key。配置版本/secret缺失时服务不就绪；派生结果与会话已存哈希不符则撤销该会话并要求重登录。密钥生成、权限、备份与恢复属于后续实现验收，不在P6-A生成真实秘密。

所有有副作用的 HTTP 请求，包括登录、注销、改密、上传、排序、归档、预览/发布/回滚，要求准确的 Origin 与对应 CSRF。拒绝缺失、`null`、多值或非批准 origin；Referer 不替代缺失 Origin。`Sec-Fetch-Site` 为 `cross-site` 时拒绝，但不能把该头或 SameSite 当唯一 CSRF防护。所有 GET/HEAD均无内容变更或发布副作用。

同源 XSS 可以绕过浏览器级 CSRF，必须同时落实文本转义、图片重新编码、禁止富HTML/任意脚本和管理页面资源约束，不能声称 CSRF解决了XSS。

### 3.4 限速与资源上限

- 单来源 IP + 规范化账户名：15分钟内最多5次失败，之后返回429；匿名 challenge也按来源与全局配额限制。
- 全局密码验证并发最多2个、等待队列最多4个，排队超过2秒返回429；单次Argon内存预算至少64MiB，并为Go/SQLite/图片处理另留容器空间。
- 未知账户执行固定成本的虚拟哈希验证，外部错误统一；仍先经过限速与并发闸门，避免任意请求耗尽内存。
- 不因任意攻击者输入永久锁死管理员；失败计数有时间窗与有限保留。审计只记事件类型、脱敏来源及计数，不存密码。
- IP只从已核实的可信代理链取值；不信任客户端伪造的 X-Forwarded-For/Cloudflare头。未配置可信代理时使用直接连接地址，不凭请求头扩大信任。
- 图片解码并发限制为1，构建/激活任务互斥。请求体、读头、上传时间、分页及审计保留均设上限。具体容器资源限制须在后续真实测试中校准。

限速参数属于首版设计基线，P6-B必须实测并发和恢复；不得仅因字段存在就标记抗暴力破解或抗DoS验收通过。

## 4. 后台页面与操作边界

| 页面                | 内容与操作                                              | 必须呈现的状态                                                   |
| ------------------- | ------------------------------------------------------- | ---------------------------------------------------------------- |
| `/admin/login`      | 登录、申请challenge                                     | 统一错误、限速等待、会话过期；不泄露账户是否存在                 |
| `/admin/`           | 项目/分类总数、公开快照项目数、草稿差异、精选与近期事件 | 草稿/已发布分离，worker离线、状态待核对、安全门槛提示            |
| `/admin/projects`   | 项目列表、创建、编辑、归档、恢复、显式排序              | 未确认字段、封面占位、无入口、版本冲突；不靠拖拽实现唯一排序方式 |
| `/admin/categories` | 分类创建、编辑、删除空分类与原子排序                    | 稳定slug、项目引用、空分类、版本冲突；不能删除仍被使用的分类     |
| `/admin/profile`    | 品牌、个人介绍、能力、原则、公开联系、可选简历          | 已确认/待补文案，不推断履历或Git邮箱                             |
| `/admin/settings`   | 三页SEO、分享图、允许的展示设置                         | 主域只读，不提供端口、代理、命令、Git地址或任意环境变量编辑      |
| `/admin/media`      | 上传、预览、alt、引用、软删除申请                       | 解码中/失败/就绪/被引用；原件与公开派生图区别                    |
| `/admin/preview`    | 提交快照预览、进入认证网关                              | 明示非公开、快照版本及过期时间                                   |
| `/admin/releases`   | 历史版本、任务日志摘要、发布与回滚                      | 完整结果与失败原因，活动版本核对状态；不能以点击成功代替上线成功 |
| `/admin/account`    | 改密、注销                                              | 当前会话撤销说明，不显示密码或token                              |

表单保存只更新草稿，不自动发布。发布和回滚需展示具体快照/目标版本、差异摘要、资料与风险门槛；不能把“预览成功”包装成“正式发布成功”。危险操作要求最近5分钟内完成密码再认证；再认证凭据只绑定当前会话，不接受前端布尔字段宣称已认证。

前端不会因接口返回相同origin的未知路径而任意跳转。未实现菜单隐藏或明确标注不可用；P6-A骨架不得展示能误导用户的成功按钮。保留键盘焦点、错误关联、状态播报、移动布局与深浅主题；不以一个大表单覆盖全部工作区。

管理路由的 SPA fallback只适用于登记的 `/admin` 页面。`/api/admin/v1/**`、静态资源不存在及未知API必须返回对应JSON/404，不能回退管理HTML或公开站HTML。

管理HTML使用`X-Robots-Tag: noindex, nofollow, noarchive`，不进入公开sitemap；不加载第三方分析、远程字体或远程脚本。后续管理构建应能使用无`unsafe-eval`的同源CSP，禁用object、外部form action与被第三方frame嵌入；不得把服务端秘密放入`VITE_*`编译变量。默认用带`noopener noreferrer`的新窗口打开认证预览，不为预览削弱所有后台页面的frame策略。准确CSP及Vite产物兼容性属于P6-C浏览器验收。

## 5. 内容字段、兼容与校验

公开快照使用明确版本号 `schemaVersion: 1`，只包含当前静态站需要的公开字段；后台审计、账户与编辑状态不进入快照。所有长度上限按Unicode码点计算，并另设总JSON字节上限256KiB；禁止控制字符，允许正常换行的字段单独声明。

### 5.1 项目

| 字段                       | 契约                                                                                                        |
| -------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `id`                       | 服务端ID，不允许编辑；与静态Project.id映射保持稳定                                                          |
| `slug`                     | 1～64位小写字母、数字、单连字符，首尾字母/数字；全工作区唯一；不作为磁盘路径直接拼接                        |
| `name`                     | 必填1～80字                                                                                                 |
| `summary`                  | 必填1～500字纯文本，不接受HTML/Markdown                                                                     |
| `description`              | 0～20,000字纯文本，允许正常换行，不接受HTML/Markdown；不自动新增项目详情路由                                |
| `category`                 | 已存在分类的稳定slug；初始为`website`、`application`、`open-source`，可通过分类管理扩展                     |
| `techStack`                | 最多20项，每项1～40字，去除空项/精确重复；空数组合法并显示待确认                                            |
| `status`                   | `unconfirmed`、`planning`、`in-development`、`live`、`maintained`；不能由封面或URL自动推断                  |
| `featured`                 | 布尔值，首页仍按推荐顺序最多取6项                                                                           |
| `visible`                  | 布尔值；false时不进入公开快照、首页、分类计数和访客搜索，后台仍可编辑                                       |
| `order`                    | 非负整数；由原子排序端点维护，不允许多个独立保存产生半排序状态                                              |
| `cover`                    | 由受控mediaId或仓库可信资源ID解析，客户端不能提交任意绝对路径/远端图片URL                                   |
| `coverAlt`                 | 1～200字纯文本；封面类型为占位时说明占位，实际故障后备逻辑保留                                              |
| `coverKind`                | `placeholder`或`screenshot`，与状态独立；截图必须有用户确认公开记录                                         |
| `demoUrl`、`repositoryUrl` | 可空；非空为已确认的HTTPS公开URL，无userinfo/控制字符/非预期协议；拒绝本机、内网、管理后台入口              |
| `archivedAt`               | 后台只读归档时间；归档时同事务设置visible=false，恢复后仍保持隐藏，须显式设置可见并重新发布；不销毁历史版本 |

链接确认是管理员的内容确认流程，API不自动发起远程探测、抓图或重定向跟随。URL格式合法不等于入口真实可用；发布前仍需独立人工/受控HTTP验证。未提供链接时继续隐藏对应入口，不生成假链接。

首版不新增项目详情路由。保留静态卡片的分类/状态文案、图片比例、AVIF/WebP sources兼容及故障后备，不把`isPlaceholder`兼容字段变成发布状态开关。

管理API中的`cover`是受控引用对象：`{"kind":"media","id":"<mediaId>"}`或`{"kind":"builtin","id":"<可信资源ID>"}`，均由服务端注册表解析；它不是URL。快照适配时才转换成现有Project的`cover`、`coverSources`等公开路径。PUT对象使用明确字段，空可选URL用null表示清除；项目ID、order、归档时间是只读，创建默认追加到末尾，排序另走原子端点。PATCH媒体只接受登记的局部字段，不提供通用JSON patch路径。

### 5.2 分类

分类字段为服务端`id`、稳定`slug`、`name`（1～80字）与非负整数`order`。slug使用与项目相同的1～64位格式，创建后不可编辑，全工作区唯一；显示名称可以修改，不改变已有筛选URL。

初始化导入`website`、`application`、`open-source`三类及现有中文文案，但这三类不是永久硬编码白名单。管理端可以创建新分类，访客分类列表、查询解析与计数后续由快照中的分类注册表产生；未知slug仍回退全部项目，不能把任意query当成可信分类。

分类排序要求完整当前分类ID有序数组，在一个revision事务内完成。仅无任何项目草稿引用的空分类可删除；隐藏/归档项目仍算引用，存在引用时返回409，需先通过显式草稿操作迁移分类。历史不可变快照内自带当时分类元数据，删除空草稿分类不能改写旧快照或旧页面。本版不额外增加分类归档字段。

这是P6-D数据适配改造点：现有`ProjectCategory`联合类型与`parseCatalogQuery`三类白名单必须一起迁移，不能只改后台数据库让前端悄悄丢失新分类。既有三类slug与筛选URL保持兼容。

### 5.3 品牌与关于页

`profile.site`映射现有`siteProfile`：`name`（1～80字）、`role`（1～120字）、`introduction`（最多8段，每段1～500字）、`directions`（最多10项，每项40字）、`technologies`（最多30项，每项40字）、可空`githubUrl`。

`profile.about`映射现有`aboutProfile`：`brandIntroduction`（1～1,000字）、`personalIntroduction`（最多12段，每段1～1,000字，可空）、`capabilities`（最多10组，每组标题80字及最多30项技术）、`principles`（最多10项，标题80字、描述500字）、`contacts`（最多10项，label80字、description300字、明确确认的HTTPS/mailto地址）、可选`resume`。

个人头像使用可空`avatarAssetId`，品牌图使用登记用途的可空媒体引用；与项目封面一样只接受受控素材ID，不接受文件系统路径或远程图片抓取。未设置头像不新增空白视觉区域。

简历只能引用受控公开文件ID或已确认的HTTPS地址；本阶段不开放任意PDF/附件上传。联系邮箱由用户明确输入，绝不由Git提交邮箱、服务器账户或代码注释推断。空个人介绍、无简历与无联系方式都是合法状态，不能伪造履历来通过必填检查。

### 5.4 设置与SEO

管理端可维护三个既有页面的`title`（1～100字）、`description`（1～300字）及经确认的分享图媒体引用；不允许直接输入`<meta>`、canonical、sitemap XML或脚本。

`settings`明确包含`siteTitle`（1～100字）、`siteDescription`与`defaultSeoDescription`（各1～300字）、`homeIntroduction`（最多8段、每段1～500字）、`footerText`（0～300字）、可空`defaultShareAssetId`、`socialLinks`（最多10个已确认HTTPS链接）及上述`pages`三页SEO对象。每页显式值优先，否则使用默认SEO；分享图同样按页面值、默认图、仓库品牌图回退。首页简介与`profile.site.introduction`是同一持久化字段的两个视图，不能各存一份：两个PUT都经同一revision事务读写`siteProfile.introduction`，返回规范化值，并保留另一个视图的其他字段。页脚只接受纯文本，年份由渲染器生成，不接受HTML。

正式origin由受控服务配置固定为`https://xiaoworks.com`，API只读返回，不能通过表单改成任意域名。页面路径为`/`、`/projects/`、`/about/`，canonical与OG URL由固定origin加路径生成。`robots`、sitemap、分享图绝对地址与客户端页面必须由同一个不可变快照产生。发布ID、预览前缀和管理路径不得出现在正式canonical/sitemap中。

不生成虚假的更新时间、项目上线时间、工作经历或结构化获奖信息。资料待确认仍是合法公开状态，用户已允许首版明确占位；编辑器应明确显示该状态，不自动升级为真实已验证内容。

### 5.5 HTTP 字段与持久化映射

HTTP 契约的字段白名单与长度限制可以严于 SQL 的最终存储边界。例如项目 API 的 name/summary/slug/coverAlt 上限为 80/500/64/200，而表中分别允许 160/2,000/80/500；表约束不意味着 API 接受到存储上限。导入、恢复与工作区公开投影也必须经过相同运行时 schema，不能借内部流程绕过真实性与 URL 校验。

`/profile` 与 `/settings` 是逻辑 API 视图，底层只使用 `workspace_documents` 的 `site`、`profile` 两种 kind，不新增 `settings` kind。实现时按登记的字段映射读写相应 JSON，并在同一个 revision 事务中维护媒体引用；逻辑视图的 PUT 只替换本视图拥有的字段，不能顺带清空另一视图的内容。

项目 API 的稳定分类 slug 经分类注册表解析为 `category_id`，响应中的 `order` 映射 `sort_order`；媒体逻辑 ID 映射不可变的 `assets` 与可编辑的 `asset_metadata`，PATCH 只能改变后者允许的字段。HTTP 时间使用 RFC 3339 UTC，数据库时间使用 Unix 秒，转换由受控服务显式完成。

## 7. 图片上传与素材生命周期

只接受真实可解码的PNG、JPEG、WebP输入。扩展名、浏览器MIME和真实格式必须一致；不一致拒绝，不靠重命名放行。禁止SVG、GIF、HTML、PDF、压缩包、多文件上传、URL抓取与远程截图。AVIF上传延后到有受控解码器及安全测试的阶段；现有仓库可信静态AVIF/WebP/SVG占位资源继续兼容，不经过开放上传接口。

限制为单原文件最多10MiB（10,485,760字节）、单边最多8,192像素、总像素最多25,000,000；multipart总体最多11MiB。先限流/鉴权/CSRF/版本，再限长落入私有临时文件、读取格式尺寸并校验乘法溢出，最后受限解码。不能先完整解码巨图再检查尺寸。

解码并重新编码后才生成可引用派生图；不原样公开用户文件。派生图去除EXIF/GPS/注释及不需要的元数据，保留必要的正确色彩/透明度。PNG/JPEG使用审查过的编码器；WebP输入需要显式引入并锁定受审查解码依赖，不能误称Go标准库已经内置WebP编码。首版可将WebP解码后输出PNG（有透明度）或JPEG，暂不强制增加WebP/AVIF编码依赖。

解码并发1，限制临时磁盘与派生输出大小；请求取消/超时不能被描述成必然中断底层图片解码。实际CPU/内存峰值、恶意文件和库版本需P6阶段实测，容器资源限制提供最后边界。

媒体记录包括`id`、字节内容SHA-256、输出MIME/扩展名、宽高、字节数、alt、受限显示名称、创建时间、公开确认状态及引用摘要。磁盘文件名由内容哈希与服务端确定扩展名构造，不使用原始文件名，也不接受客户端路径。相同字节可去重，不同字节必须新对象，不能覆盖旧URL。

私有原件和派生媒体在发布前均只能经认证网关访问；猜到哈希也不能从公开静态入口读取草稿文件。正式发布只将该快照需要的已确认派生图复制到该版本的不可变公开媒体树；公开URL例如`/_releases/<releaseId>/media/<sha256>.jpg`，不泄露内部目录。同内容可以在私有存储去重，但公开引用始终包含明确发布ID并随对应资源保留。真实截图确认与媒体解码成功是两个独立条件，ERP必须另外确认不含敏感业务信息。

上传在私有临时文件处理，完成校验后通过原子文件操作和数据库事务登记。若处理期间工作区revision变化，返回409；暂存文件由保守清理队列处理，不能先修改项目引用再宣称上传失败。任何中断都不能覆盖已发布文件。

删除默认软删除；草稿、待执行任务、有效预览、保留发布、当前/回滚版本或备份引用中的媒体不能物理删除。引用计数不是唯一GC依据，GC还需遍历不可变manifest并检查进行中任务；至少30天宽限，首次仅提供dry-run清单与管理员受控执行。P6-A不实现自动GC，不提供任意路径删除接口。

公开历史资源为了旧页面与回滚会被保留，因此删除新草稿中的引用不等于从互联网撤回旧内容。误公开敏感资料属于专门的撤回事件，应停止发布并按授权处理相关旧资源、缓存与备份，不能靠常规GC声称已彻底删除。

## 8. 预览、任务与发布结果

### 8.1 不可变快照

提交任务时在同一数据库事务内校验工作区、公开资料边界、媒体状态，创建唯一snapshotId、规范化公开JSON及SHA-256，并登记任务。snapshot保存公开投影schema版本、工作区revision、媒体哈希引用和创建时间；源码SHA与构建器版本由受控配置提供并记入release/manifest，不接受普通表单输入。封存后不能再原地编辑，后续保存形成新revision/快照。

任务主状态`status`只允许`queued`、`running`、`reconciling`、`succeeded`、`failed`、`cancelled`。成功流转为`queued → running → reconciling → succeeded`，在reconciling核验本任务proof后才能成功；激活前已确认未改变旧版的构建失败可由running进入failed。尚未领取的queued任务可取消为cancelled。租约中断或文件系统与数据库不一致也进入reconciling，不能仅靠超时重新执行一次可能已成功的激活。

执行阶段单独存为`phase`，只允许`building`、`validating`、`prepared`、`activating`、`recovery_required`，排队和终态均为null。领取任务后status=running；发布阶段按building、validating、prepared、activating推进。预览不进入activating；回滚可跳过building，在验证保留目标后进入prepared/activating。需要恢复核对时status=reconciling、phase=recovery_required；终态清空phase，最后执行阶段保存在追加审计中，不用阶段名替代主状态。

API以202接受任务，随后管理端查询状态。首版在SQLite事务与唯一性约束中只允许**一个未完成任务**，包括queued、running或reconciling，预览/发布/回滚全部串行；已有未完成任务时新提交返回409 JOB_CONFLICT，不维护四任务等待队列。worker不可用返回503，不返回伪成功。任务日志只公开脱敏摘要，不返回完整环境、命令、绝对路径或Cookie。

任务响应的最小字段为`id`、`kind`、`status`、可空`phase`、`snapshotId`、`workspaceRevision`、可空`releaseId/targetReleaseId`、`createdAt/startedAt/completedAt`、可空脱敏`error`及`activeVerified`。租约原token、activation token、原始receipt内容和物理路径不返回浏览器。202响应只含任务标识/状态与同源statusUrl；只有完成本次对账的终态响应可以宣告成功。创建快照/任务本身不递增草稿revision。

### 8.2 认证预览网关

预览页面和全部资源必须通过`/api/admin/v1/previews/{previewId}/...`登记的认证网关路径访问，每个请求均校验有效会话。只允许已完成验证且未过期的预览；过期/失败/未知资源404。预览默认24小时过期，过期后停止访问但不删除仍被任务引用的媒体。

网关返回`Cache-Control: no-store`及`X-Robots-Tag: noindex, nofollow, noarchive`，预览HTML另带robots noindex；不写入公开sitemap。robots/noindex不是权限控制，真正的边界是每次请求的会话验证与私有存储。

预览构建使用由系统生成的独立baseURL和媒体前缀，所有HTML、脚本、Nuxt版本资源、图片、favicon及theme-init必须指向该认证网关。现有绝对`/images/`、`/theme-init.js`不能直接照搬并假设生效。canonical仍是固定主域的正式页面路径，不包含预览前缀。

预览产物不可直接promotion成生产产物：正式发布对相同不可变快照，以正式baseURL重新构建并完成验证。构建器源码与依赖版本保持一致，不能因为两次构建使用同一个snapshotId就跳过资源检查。P6-D必须验证子路由、媒体、主题与内部导航均未绕过网关或暴露草稿。

预览只展示固定源码生成的页面，不支持上传HTML/脚本，也不执行内容中的模板。若使用iframe，不把同源且允许脚本的iframe当作强隔离沙箱；管理页面、公开站代码与内容转义仍在同一信任评估范围。

### 8.3 正式激活与回滚

worker只能执行固定、预先安装依赖的构建程序，对选定快照生成staging，校验页面/SEO/资产/manifest后再原子切current。旧HTML所需的版本化bundle与不可变媒体保留；不能只替换HTML而清除旧JS、payload或图片。未来关闭payload extraction、版本化buildAssetsDir与发布目录挂载的行为必须真实验证，P6-A不声称已经解决跨版本一致性。

回滚只引用仍存在且验证通过的releaseId，不接受路径/镜像/命令。回滚也是互斥任务，需要再认证、审计和真实current核对。它切换内容版本，不自动回退Git源码、Go/API数据库结构、Docker镜像、OpenResty或DNS。

API不能因worker发来`succeeded`就直接向前端报告成功。对publish/rollback，必须通过只读发布根核对current目标在受控目录内、本任务activation token、manifest/receipt哈希、快照ID/哈希、源码/构建器版本及实际活动版本，并完成固定本地HTTP核验。对preview，只核验该任务私有预览的manifest/receipt与快照，不设置activation token也不改变current。证明缺失、文件不一致或未知current时保持`status=reconciling`、`phase=recovery_required`并停止后续激活；不能用数据库active字段覆盖未知文件系统事实。

## 9. 私有 UDS worker 协议

P6-A骨架不实现worker或UDS；本节约束后续实现，不能视为已验证进程隔离。

API在仅与worker共享的socket卷内创建并监听Unix Domain Socket，权限`0600`，owner为专用UID10001；worker同UID拨入，socket不监听TCP。目录权限限制为专用服务身份，禁止无关容器挂载。API检查对端凭据，协议版本和固定worker标识；socket只在受控位置创建，拒绝替换为任意symlink/文件。

协议是有限JSON帧，单帧最多1MiB，明确长度边界、读写超时、最大连接数与未知字段拒绝；不允许通过一条巨大消息传原始媒体。worker主动请求的操作白名单仅为：

| 操作        | 请求要点                                     | API响应/效果                                                                                                    |
| ----------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `claim`     | 固定workerId、协议版本、当前能力版本         | 原子领取唯一queued任务并改为running，返回leaseId、到期时间、固定action、快照JSON/哈希及允许的媒体ID；无任务为空 |
| `heartbeat` | jobId、leaseId、阶段                         | 校验租约并延长至有限截止；阶段不能倒退或越过验证                                                                |
| `report`    | jobId、leaseId、结构化阶段/失败码/产物proof  | 只接受该任务允许字段；成功需额外只读FS核验                                                                      |
| `reconcile` | 固定发布根读出的current/manifest/receipt摘要 | 与DB已知批准快照比对；不一致停在待核对，不自动改写current                                                       |

API不会通过此协议传shell命令、可执行文件、任意参数、网络目标、Git ref、路径或环境变量。`action`只允许固定的preview/publish/rollback枚举，由worker映射到自身固定代码。leaseId为随机高熵值，仅私有传输且不写公共日志；旧/过期租约的report拒绝。

worker没有SQLite挂载，通过claim获取最小公开快照；媒体从单独只读、内容寻址的私有派生资源卷读取，按白名单ID/哈希核对。API没有发布根写权；只有worker拥有受限staging/releases/current写卷。构建工具、依赖和源代码以固定版本只读提供，不在每次API任务中执行npm install或下载任意仓库。

并发上限首版为一个构建/激活任务；首次上线的资源预算、租约时间、崩溃恢复及进程终止需要独立测试。禁止Docker socket、特权容器、宿主根目录挂载或为了让worker工作而授予SSH/整机Docker权限。

## 10. 审计与实现验收

审计事件包括初始化/重置、登录成功失败与限速、注销/改密、草稿写入与版本冲突、媒体上传/拒绝/软删除、任务提交/阶段/失败、实际激活/回滚与状态待核对。记录操作者ID、服务端时间、requestId、对象ID、前后revision/公开快照哈希及有限错误码；不记录密码、token、Cookie、原件、完整请求体或主机敏感路径。

审计写入必须有容量和保留策略，不能在磁盘满时假装已持久化成功。SQLite迁移/备份含账户与会话，属于私有数据；数据库备份恢复后默认撤销会话，避免恢复旧token有效期。发布目录、数据库、私有媒体和审计的恢复是不同步骤，不能只备份current指针。

后续实现验收至少覆盖：

1. CLI无TTY/已有账户/错误重复密码均拒绝，数据库与日志无明文密码、原会话token；Argon参数、升级与资源上限真实检查。
2. 登录nonce过期/重放/缺Cookie/跨域、缺失/伪造Origin、CSRF错误、未知账户及限速并发；登录前后会话ID更换。
3. idle/absolute过期、轮询不续期、注销、改密撤销全部会话及重启后的校验；Cookie属性和不缓存行为通过浏览器与HTTP验证。
4. 同revision并发保存只有一个成功，另一个409；无If-Match返回428；重复幂等请求不创建多个项目/发布；排序事务无半成品。
5. 未知API/方法/字段/重复JSON键、超大body、路径穿越、伪造媒体ID、内部URL/协议均拒绝；API路径不回退SPA。
6. 伪扩展名、SVG/GIF/AVIF上传、畸形图、解压炸弹、大尺寸、超像素、重复文件、EXIF/GPS、透明度及上传中断；草稿媒体无法公开获取。
7. 预览所有资源均需认证；退出后预览与媒体不可读取；noindex/no-store、路径范围、过期、内部路由及正式canonical正确。
8. API无发布根写权、worker无DB、无Docker socket/SSH；UDS权限/对端/协议边界和未知操作实际拒绝，不仅检查Compose文本。
9. worker中断、租约过期、构建失败、校验失败、切换前后崩溃、假success proof及未知current进入可解释的失败/待核对状态，旧版本仍可服务。
10. A页面在发布B后内部导航仍完整使用A资源；刷新进入B；回滚A；媒体保留与manifest一致，staging/数据库/管理数据不进入公开bundle。

本节全部是未来验收项目，**本文未执行上述安全测试，也未宣布任何对应功能已完成**。P6-A的可验收范围仅为契约、边界、数据/状态设计及独立本地骨架；生产仍保持P5已验收版本与既有未放行状态。
