### 官方来源核对与冲突

- Alpine 3.24 官方 secdb（HTTP Last-Modified：2026-10-27 07:32:43 GMT）和官方 aports 确认 brotli 1.2.1-r0 修 CVE-2026-111497，curl 8.23.0-r0 修相关问题。当前页面没有使用这些可选解析器，采用删除未用包而不是引入运行时下载。官方证据见 `P6E-alpine-secdb.json` 与 `P6E-alpine-source.json`。
- musl 1.2.6-r3 的 Scout 告警将 CVE-2026-107891 的修复点列为 r6；官方 **3.24 分支** secdb 与 aports 均列 r3 已修。保留双方原始事实，不修改报告、不编造豁免，也不为追逐另一分支包版本混用 Alpine 仓库。正式上线前再次核对并记录最终镜像的处置决定。
- Node.js 官方 2026-10-21 安全发布列出 24.22.1 已包含本轮 Brotli/DNS/TLS 等修复；镜像固定使用该版本。Alpine 独立 brotli 包与 Node 内置 Brotli 是不同扫描范围，不能相互替代。

## 浏览器与性能补测

Chromium 的完整管理与发布操作见 `P6E-admin-browser.json`、`P6E-publishing-browser.json`。Firefox/WebKit 的公开三页面 × 五宽度 × 双主题共60组，均无页面横向溢出、无 hydration/pageerror；实际390px截图为 `P6E-firefox-mobile.png`、`P6E-webkit-mobile.png`。附加浏览器不替代 Chromium 的带账号管理验收，也不等同真实 iOS Safari/移动设备。

Firefox 在仅测试临时 profile 导入 CA，实际可信 HTTPS 登录页与浏览器 `fetch` 匿名401/no-store通过。首轮用了独立 Node APIRequestContext，其 CA 库不同导致该附加探针失败；首轮原记录仍在 `P6E-multibrowser-first.json`，修正为浏览器实际请求后最终记录在 `P6E-multibrowser.json`。WebKit 公开30组通过，但默认信任库不含此私有测试 CA，HTTPS明确 `NOT_PASSED`；未忽略 TLS 错误、未修改宿主信任库，也未声称完成其登录管理测试。

Lighthouse 13.6.0 / Chrome156 对同一真实本地静态 release 实测：首页mobile三次92/98/95，中位95，LCP中位1123.47ms、CLS0、TBT中位195.31ms；项目mobile91/LCP2265.50ms；关于mobile93/LCP1036.18ms；首页desktop100/LCP251.08ms/TBT0。全部页面 Accessibility、Best Practices、SEO 均100，所有 CLS 为0。首页传输约161.3KB，JS约104.6KB，CSS约7.5KB。原始六报告及 CPU 校准警告见 `P6E-performance-summary.json` 和 `P6E-lighthouse-*.json`。

这些是本地 Docker/模拟节流/隔离测试内容的导航实验室数据。TBT **不是 INP**，无真实用户 INP/CrUX；无可比 P6-D 基线，不以其他阶段工具/内容假作前后对比。保留 forced-reflow、请求链等审计建议，不为评分放松安全或改视觉。首轮受限 Chrome DevTools 启动失败未计分，允许的本地隔离重试完成。

## 内容真实性

Blog/Nav/ERP 的技术栈、状态、外链、截图继续以现有配置的“待确认”状态为准。测试上传的合成图只能进入隔离测试卷；不能作为真实项目资料或迁入正式数据库。ERP 真实截图必须由用户确认可公开且不含业务数据。个人资料不增加未经确认的学历、履历或联系方式。

## 既有生产门槛

默认 Worker profile 与正式发布开关继续关闭。未连接德国服务器，也未改变 V1.0 镜像及原用户未接受的生产风险门槛。本地新镜像扫描或测试通过不能据此宣称生产旧版本已修复、已升级或已获风险接受。

本轮已消除扫描所报的运行镜像 critical/high，但 deepmerge low、openpgp模块告警及 musl 官方来源冲突仍如实保留。正式部署前需结合完整故障/备份/更新验收、这些残余风险的处置决定与用户独立授权判断发布条件；安全工具零高危不等于整个系统零风险。
