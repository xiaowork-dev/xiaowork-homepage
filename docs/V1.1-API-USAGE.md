# XiaoWork V1.1：管理 API 与 P6-C 客户端对接说明

更新：2026-10-27。本文描述 P6-B 已实现的 Go 接口与 P6-C 的真实 Vue 管理客户端。P6-C 未修改 Go API 契约；静态预览、构建、发布和内容回滚仍属于 P6-D。所有编辑均保存到私有草稿，不改变 V1.0 公开 HTML、图片和 SEO。

## 1. 本地准备与账户初始化

先按 [独立开发环境说明](V1.1-DEVELOPMENT.md) 准备并启动 `compose.admin-dev.yaml`，信任专用本地 HTTPS CA。不能使用 `curl -k`、`InsecureSkipVerify` 或不安全 Cookie 代替可信 HTTPS 验收。生产主域固定为 `https://xiaoworks.com`；本地允许的认证 origin 必须是配置中的一个精确 HTTPS 回环地址，不能用任意 localhost 端口。

```powershell
docker compose -f compose.admin-dev.yaml exec -it api /homepage-api init-admin
```

命令交互读取账户名及两次隐藏密码。密码为 12～128 个 Unicode 字符，最多 1,024 个 UTF-8 字节，按原始字节处理。没有默认账户或密码，不接受密码命令行参数、环境变量、管道或公开注册。已有账户时拒绝覆盖。受控离线重置使用相同 TTY 限制：

```powershell
docker compose -f compose.admin-dev.yaml exec -it api /homepage-api reset-admin
```

重置撤销全部会话及预登录 challenge。不要把真实密码、Cookie、CSRF、会话密钥、数据库或上传目录放进请求脚本、提交、截图或交付日志。

P6-C 管理入口为 `https://localhost:3443/admin/`，包含概览、项目、分类、素材、品牌资料、网站设置及改密页面。只使用已经初始化的账户，没有公开注册。独立管理应用的启动、构建、可信 CA 与专用 E2E 方法见 [开发环境](V1.1-DEVELOPMENT.md)，日常操作见 [管理操作说明](V1.1-ADMIN-USAGE.md)。API 仍仅通过本机隔离 HTTPS 网关访问，不能把该开发编排直接用于生产。

## 2. 通用契约

统一前缀为 `/api/admin/v1`。JSON 成功响应为 `{ "data": {...}, "requestId": "req_..." }`，错误为 `{ "error": { "code": "...", "message": "...", "fields": [] }, "requestId": "req_..." }`。时间使用 RFC 3339 UTC。敏感响应使用 `Cache-Control: no-store` 和 `X-Robots-Tag: noindex, nofollow, noarchive`，不提供 CORS 凭据访问。

JSON 必须使用 `Content-Type: application/json`，普通请求最多 256 KiB，认证最多 8 KiB。字段名大小写严格，拒绝未知字段、重复键、尾随第二个 JSON 值、非法 UTF-8 和过深嵌套。读取接口不应发送请求体；只使用端点登记的查询参数，不能提交服务器路径、命令、Git ref 或部署环境变量。

除 challenge/login 外，接口均先检查服务端 Session。所有写请求再检查精确 `Origin` 和 `X-CSRF-Token`；缺失 Origin、`null`、外站 Origin、跨站 fetch 或错误 CSRF 均拒绝。浏览器使用同源 `fetch` 的 Cookie 模式，不把会话令牌存入 localStorage、URL 或响应 JSON。

### 2.1 工作区版本与幂等

`GET /workspace` 及内容读取响应给出 `data.revision: "ws-N"` 和 `ETag: "ws-N"`。草稿写操作必须带 `If-Match: "ws-N"`。成功后读取并保存新 revision，不能继续使用旧值。

- 缺少 If-Match：`428 REVISION_REQUIRED`。
- 格式错误、弱 ETag、通配符、多值：400。
- 版本落后：`409 REVISION_CONFLICT`，包含 `error.currentRevision`。客户端保留未保存输入，显式刷新或重新应用，不能自动重试覆盖。
- 创建项目还必须带 `Idempotency-Key`：16～128 个字母、数字、`-`、`_`。同一账户、端点、键和请求返回原结果；相同键而请求不同返回 `409 IDEMPOTENCY_CONFLICT`。成功记录至少保留 24 小时。

认证操作不需要工作区 If-Match。数据库在实际草稿事务内再次校验会话，避免请求开始后退出、改密或会话失效仍继续写入。事务包含内容、引用、revision、变更记录与审计，任一步失败均不提交。

## 3. 认证流程

| 方法与相对路径              | 请求                                                                            | 结果                                                                                       |
| --------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `GET /auth/login-challenge` | 无查询参数                                                                      | `loginNonce`、`expiresAt`，设置预登录 Cookie                                               |
| `POST /auth/login`          | `{ "username": "<账户>", "password": "<仅运行时输入>" }`；nonce 放 X-CSRF-Token | `administrator`、`csrfToken`、`expiresAt`、`idleExpiresAt`、`reauthUntil`；设置会话 Cookie |
| `GET /auth/session`         | 无请求体/查询参数                                                               | 当前账户、相同的 CSRF 和截止时间；无会话 401                                               |
| `POST /auth/reauth`         | `{ "password": "<当前密码>" }`                                                  | `reauthUntil`，最长 5 分钟且不超过会话绝对期限                                             |
| `POST /auth/logout`         | 无请求体，或严格空对象 `{}`                                                     | 204，撤销当前会话并清 Cookie                                                               |
| `POST /auth/password`       | `currentPassword`、`newPassword`、`confirmPassword`                             | 204，撤销全部会话（包括当前），要求重新登录                                                |

首次读取 challenge 后，浏览器保留 `__Host-xiaowork-login` Cookie。提交登录时同时发送精确 Origin、该 Cookie 与 `X-CSRF-Token: <loginNonce>`。nonce 5 分钟有效，来源绑定且单次消费；密码错误、格式错误或并发重试后都需申请新的 nonce。

登录成功后 Cookie 为 `__Host-xiaowork-admin`，固定 `Secure; HttpOnly; SameSite=Strict; Path=/`，不设置 Domain。数据库只保存随机会话令牌和 CSRF 的哈希；CSRF 由受控持久秘密与会话 Cookie 派生，`GET /auth/session` 刷新不会使其他标签页的 CSRF 失效。

空闲期限 30 分钟，绝对期限 12 小时。有效交互请求成功后最多每 30 秒合并更新活动时间；`/auth/session`、`/dashboard`、`/jobs` 轮询不续期，404 和非法表单不续期。过期、退出、离线重置、改密或秘密不匹配均拒绝旧会话。

每个来源和规范化账户名在 15 分钟窗口内最多 5 次失败验证，之后 429；未知账户执行同成本的虚拟 Argon2id 校验。密码验证最多 2 个并发、4 个等待，最多等 2 秒；容量不足返回 `429 AUTH_CAPACITY`。匿名 challenge 每来源最多 10 个、全局最多 1,000 个有效未使用记录。限速使用 SQLite，服务重启不会清空窗口。仅信任显式配置代理地址的转发头，客户端自带的 Cloudflare/X-Forwarded 头不能扩大信任。

## 4. 工作区与项目

| 方法与相对路径                | 实际行为                                                            |
| ----------------------------- | ------------------------------------------------------------------- |
| `GET /workspace`              | 完整草稿、分类、profile、settings、revision、初始化/校验状态        |
| `GET /dashboard`              | 草稿统计、已发布状态、近期修改与审计摘要；P6-D 前不捏造公开发布数量 |
| `GET /projects`               | `archived=false`（默认）/`true`/`all`，`limit` 1～100，`cursor`     |
| `GET /projects/{id}`          | 项目可编辑字段、只读 ID/顺序/时间和 revision                        |
| `POST /projects`              | 完整项目 DTO；CSRF、If-Match、Idempotency-Key；201                  |
| `PUT /projects/{id}`          | 完整替换可编辑字段，不能改 ID、时间或直接改顺序                     |
| `POST /projects/{id}/archive` | JSON `{}`；归档并隐藏，保留媒体/历史                                |
| `POST /projects/{id}/restore` | JSON `{}`；恢复草稿，之后显式检查展示状态                           |
| `PUT /projects/order`         | `{ "ids": ["<有效项目ID>", "..."] }`，完整的未归档项目有序集合      |

项目 DTO 示例沿用现有明确占位的 Blog 信息，仅说明字段结构。创建新的项目时使用新的 slug；修改现有项目从 GET 响应提取可编辑字段，不能把整个响应（含 ID/时间）原样 PUT。

```json
{
  "slug": "blog",
  "name": "XiaoWork Blog",
  "summary": "记录技术探索、开发过程与实践心得，让经验沉淀为可以分享的文字。",
  "description": "",
  "category": "website",
  "techStack": [],
  "status": "unconfirmed",
  "featured": true,
  "visible": true,
  "isPlaceholder": true,
  "cover": { "kind": "builtin", "id": "builtin-cover-blog" },
  "coverAlt": "XiaoWork Blog 占位封面，真实截图待补充",
  "coverKind": "placeholder",
  "demoUrl": null,
  "repositoryUrl": null
}
```

`category` 是已存在的稳定分类 slug。`status` 允许 `unconfirmed`、`planning`、`in-development`、`live`、`maintained`。封面引用使用 `builtin` 或 `media` 逻辑 ID，不接受文件路径。真实上传图片先上传、核对公开使用确认，再作为截图引用；未确认的 Blog/Nav/ERP 资料继续保持占位、空技术栈及无外链。

名称上限 80 字符，简介 500，详情 20,000，技术标签最多 20 个、每个 40 字符，coverAlt 上限 200。文本不接受富 HTML 或脚本；前端仍需用文本插值，不得用 `v-html`。URL 仅允许已确认的公开 HTTPS 地址；拒绝凭据 URL、危险协议、本机/私网、管理路径和无效地址。API 校验不代表项目已经上线或地址可访问，也不会主动抓取该 URL。

项目/分类分页游标绑定读取时的 workspace revision 与筛选条件。列表改变后旧游标返回 409，应重新加载第一页；不要自行拼接游标。

## 5. 分类、个人资料与网站设置

| 方法与相对路径                   | 请求/结果                                                   |
| -------------------------------- | ----------------------------------------------------------- |
| `GET /categories`                | 分类、引用数量、revision；支持 limit/cursor                 |
| `GET /categories/{id}`           | 单个分类                                                    |
| `POST /categories`               | `{ "slug": "<稳定slug>", "name": "<名称>" }`；201           |
| `PUT /categories/{id}`           | `{ "name": "<名称>" }`，不允许改 ID/slug                    |
| `DELETE /categories/{id}`        | 仅允许无项目引用的分类，引用中返回 409                      |
| `PUT /categories/order`          | `{ "ids": ["<全部分类ID>", "..."] }`，拒绝重复/遗漏/未知 ID |
| `GET /profile`、`PUT /profile`   | 读/完整替换 profile，维护图片引用                           |
| `GET /settings`、`PUT /settings` | 读/完整替换允许的展示和 SEO 字段，维护图片引用              |

profile 请求顶层只有 `site`、`about`：

| 对象    | 完整可编辑字段                                                                                                                                                                                               |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `site`  | `name`、`role`、`introduction: string[]`、`directions: string[]`、`technologies: string[]`、`githubUrl: string/null`、`avatarAssetId: string/null`、`brandAssetId: string/null`                              |
| `about` | `brandIntroduction`、`personalIntroduction: string[]`、`capabilities: {title,technologies[]}[]`、`principles: {title,description}[]`、`contacts: {label,description,url}[]`、可选 `resume: {label,url}/null` |

个人技术栈与技术方向直接在 profile 数组维护，项目技术栈在各项目 `techStack` 维护；没有独立的“标签数据库”或技术栈 CRUD 端点。公开联系允许明确的 HTTPS 或不带查询参数的 `mailto:`，不从 Git 邮箱推断公开联系方式。未填写的可选链接用 null，集合用 `[]`。

settings 请求字段为：

```json
{
  "siteTitle": "<已确认标题>",
  "siteDescription": "<已确认描述>",
  "defaultSeoDescription": "<默认SEO描述>",
  "homeIntroduction": ["<首页介绍>"],
  "footerText": "<页脚文字>",
  "defaultShareAssetId": null,
  "socialLinks": [],
  "pages": {
    "home": { "title": "", "description": "", "shareAssetId": null },
    "projects": { "title": "", "description": "", "shareAssetId": null },
    "about": { "title": "", "description": "", "shareAssetId": null }
  }
}
```

这是结构示意，不能作为真实资料导入。PUT 完整替换本视图，先读取现值再编辑；不会顺带清空另一视图。不存在 domain、baseURL、端口、服务器目录、Compose、Cloudflare 或命令编辑字段；提交这些未知字段返回 400。P6-C 表单经这些接口保存 SEO 草稿，直到 P6-D 发布完成前不会修改公开 canonical、sitemap 或 HTML meta。

## 6. 图片 API

| 方法与相对路径            | 行为                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------- |
| `GET /media`              | `limit` 1～100、`cursor`、`status=active/deleted/all`；返回 `items`、`nextCursor`              |
| `GET /media/{id}`         | 元数据、引用数量、受保护的 `contentUrl`，不返回磁盘路径                                        |
| `POST /media`             | CSRF/If-Match；multipart 只有一个名为 `file` 的文件，无其他字段；201                           |
| `GET /media/{id}/content` | 认证后的派生图片；精确 MIME、nosniff、no-store                                                 |
| `PATCH /media/{id}`       | 仅 `alt`、`displayName`、`publicUseConfirmed`、`publicConfirmationNote`；至少一项，不能为 null |
| `DELETE /media/{id}`      | 软删除；草稿项目、个人资料/设置或历史快照引用中返回 `409 MEDIA_REFERENCED`                     |

原图最多 10 MiB、multipart 最多 11 MiB，单边最多 8,192、总像素最多 25,000,000，派生文件最多 32 MiB，一次解码并发。接受实际格式、MIME、扩展名一致的静态 PNG、JPEG、WebP；拒绝 SVG、GIF、AVIF、可执行文件、路径文件名、伪造 MIME 和危险/损坏图片。AVIF 上传暂未实现，保留已有静态资源格式能力不等于支持后台上传。

所有上传都解码并重新编码：JPEG 输出 JPEG，PNG/WebP 输出 PNG，剔除原文件元数据。服务端生成不可猜媒体 ID，磁盘按派生内容哈希存放；同内容不覆盖既有文件。文件位于独立持久卷，不进入公开静态根。软删除不立即删除文件，物理垃圾回收另行设计；失败事务可能留下无引用派生文件，不能通过全局清理掩盖。

新建素材默认没有公开使用确认；重复内容复用既有素材及确认状态。选用真实截图前，管理员应核实图片可公开且不含敏感信息，再 PATCH `publicUseConfirmed: true` 并填写说明。该确认只代表管理员的内容声明，不自动等于静态发布成功。

## 7. P6-C 客户端与尚未实现的边界

`/publish-jobs`、`/preview-jobs`、`/rollback-jobs`、`/jobs`、`/releases`、`/previews/` 在通过会话/Origin/CSRF 检查后返回 `503 WORKER_UNAVAILABLE`。当前没有可执行 shell、公开构建、预览、发布或内容恢复；管理 UI 保持相应入口禁用，不把 503 包装成成功。不存在通过修改 SQLite 直接改变公开站点的流程。

独立 `admin/` 应用已接入登录/challenge/session、账户改密与退出、dashboard、项目/分类 CRUD 与排序、media 上传/元数据/私有预览、profile 和 settings。项目排序同时提供拖拽与键盘按钮。品牌与网站设置使用分组字段、动态数组和素材选择，不通过大段 JSON 编辑器替代日常表单。

客户端针对 401、403、409、413、415、422、428、429 提供错误状态与反馈，上传显示真实进度。401 清除失效的内存认证状态，并显示重新登录遮罩，保留已经挂载的未保存表单；登录恢复后重新读取 workspace 检查版本。409 保留原输入和原 revision，允许查看远端差异后显式选择重载或重试，不自动用最新 If-Match 覆盖其他标签页的修改。内部导航、浏览器返回和关闭/刷新均有未保存保护；离开确认不能代替服务器 revision 检查。

会话及密码不写入 localStorage/sessionStorage、URL 或日志；localStorage 仅记录主题。私有 `contentUrl` 通过精确同源路径检查后用于登录态图片，不作为公网永久 URL。表单文本使用 Vue 插值，不使用 `v-html`；不可信地址只作为文本或经规则校验后的外链，新窗口链接带 `noopener noreferrer`。这些描述区分已实现机制和验收结果：实际 HTTPS 浏览器测试范围、发现及修复以 P6-C 交付记录为准，不能仅凭源码推断已通过全部浏览器验收。

初始化/迁移详情见阶段数据库迁移说明；实际安全请求、预期与结果见 [认证 HTTP 证据](evidence/P6B-auth-http.txt) 及 P6-B 交付报告。旧 Nuxt node-forge high 风险继续单列，后台认证通过不代表正式发布安全门槛解除。

## 8. P6-B 认证验收基线

以下保留 2026-10-26 P6-B 阶段的实际测试记录，不冒充 P6-C 浏览器结果。HTTP 集成使用 `httptest.StartTLS` 的专用证书信任池，并断言 `InsecureSkipVerify=false`；每行请求的预期与实际状态保存在证据文件。该认证记录包含 Go 集成及容量、代理头和密码/秘密操作的独立单元测试，不能把它们全部称为公网压力测试。最终 P6-B Linux 全包补充结果另见 [安全测试记录](P6B-SECURITY-TESTS.md)。
