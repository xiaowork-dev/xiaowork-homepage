# V1.1 npm 依赖安全升级

- 日期：2026-11-08（Asia/Shanghai）
- 执行者：独立审查 Agent（Claude）
- 环境：本机检查、构建与产物对比；主服务器独立测试目录中重建六角色，并通过 Worker 做一次真实发布。没有修改正式网站、OpenResty、其他项目或 main。
- 结论：Nuxt 相关的 4 个公告已修复，生成产物内容与升级前一致，Worker 的真实构建和发布通过。剩余 3 个公告都在构建/开发工具链上，上游没有不跨大版本的修复，作为残余风险记录。

## 1. 审计结论

| 公告                                                             | 包                                                 | 级别     | 影响面                                                                                    | 处理                                                           |
| ---------------------------------------------------------------- | -------------------------------------------------- | -------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| GHSA-9v7c-q64q-vv33（点号路径段绕过 server middleware 路径匹配） | nuxt / @nuxt/nitro-server（受影响 >=4.6.0 <4.6.3） | moderate | Nitro 服务端路由（本站公开站点为静态生成，影响有限）                                      | **已修复**：升级 `nuxt@4.6.4`                                  |
| GHSA-3xf4-9g3c-4h4w、GHSA-x287-wcfc-q46c、GHSA-648h-gw55-m2g7    | @nuxt/vite-builder                                 | moderate | 只影响开发服务器                                                                          | **已修复**：随 `@nuxt/vite-builder@4.6.4` 一起升级             |

| GHSA-gcqx-w48m-w2h4（mergeObject 原型污染）                      | deepmerge（<=4.3.1）                               | low      | Nuxt 构建链                                                                               | 保留：上游没有修复版本                                         |

`npm audit` 结果：根目录去重后的公告数从 8 个降到 3 个（按受牵连包计数为 20 moderate / 6 low，原因是多个 eslint 和构建包共同依赖 minimatch/glob）。后台只有 minimatch 1 项公告（经 eslint 引入，开发期使用），没有不跨大版本的修复，本轮不改动。

**没有采用强制 overrides 跨大版本替换 minimatch/glob**：这样做会让 eslint、nitropack、`@vercel/nft` 运行在其未声明支持的大版本上，可能导致构建工具出现测试覆盖不到的故障。这三项都只出现在构建和开发期：生产运行时是静态 Nginx 和 Go；Worker 虽然在生产环境执行 Nuxt 构建，但它没有网络、输入固定（快照 JSON），也不处理外部提供的 glob 模式。残余风险需要用户确认接受，或者等上游发布修复后再升级。
