## 1. 实现内容

| 组件                                 | 内容                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `backend/internal/publishgate`（新） | 安全读取控制目录中的 `publish-authorization.json` 和 `publish-revoked.json`，任何异常都关闭 gate：要求单链接、仅属主可读写、有大小上限、严格 JSON、拒绝符号链接。授权绑定项目、固定 origin、完整源码 SHA、Worker 镜像 ID、schema、24 小时内验证过的备份，以及有效期（默认 7 天，最长 30 天）。重新授权会把旧记录归档，从不覆盖；撤销一旦写入就保留                                                  |
| `homepage-control`（只在维护镜像中） | 新增 `authorize-publish`、`revoke-publish`、`publish-status`                                                                                                                                                                                                                                                                                                                                        |
| API                                  | `XIAOWORK_PUBLISH_MODE=off\|local\|production`，兼容旧的本地开关，两者矛盾时拒绝启动。生产模式下：创建任务和 Worker 领取任务时都校验授权；已排队的任务在 gate 关闭后直接失败，进行中的任务可以完成；发布前必须有同一修订号、24 小时内成功的预览；发布和恢复每小时最多 6 个；审计记录授权 ID；状态接口返回 gate 状态和中文原因                                                                       |
| 生命周期工具                         | `deploy`、`update`、`rollback` 都不会开启生产发布。`authorize-publishing` 先核对正在运行的镜像身份，以及当前版本 24 小时内由工具验证过的备份（重新运行 verify），然后在 gate 仍关闭的状态下启动 Worker，最后才写入授权。`revoke-publishing` 和 `publishing-status` 不需要生命周期锁，紧急情况下随时可用。`backup` 会记录 `last-backup.json`；`update`/`rollback` 后的候选版本一律以发布关闭状态启动 |
| 后台前端                             | 只有在服务端报告 gate 打开时，生产环境才允许预览、发布和恢复；徽标显示"生产发布已授权"或"操作未启用"                                                                                                                                                                                                                                                                                                |

## 5. 残余与后续

- 正式项目启用需要：完成正式切换授权 → 备份 → `authorize-publishing`（需填写批准说明），并由用户另行批准。
- 撤销不会强停 Worker（保证进行中的任务可以对账），之后的 `stop` 或 `update` 会关闭它。
- 第二因素（TOTP）按 D3 另行排期。被盗会话加上已知密码时，在授权有效期内仍可发布；这一风险由频率上限、先预览、一键恢复和宿主撤销来限制。
- 仍未满足的正式上线条件：npm 依赖升级、新镜像组的浏览器 UI、并发和故障注入重测、异地备份与告警、生产宿主上的 Node 运行方式（本次验收使用隔离目录中经 SHA256 校验的官方 Node 包）。
