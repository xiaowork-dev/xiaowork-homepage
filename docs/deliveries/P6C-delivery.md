# P6-C 交付：Vue 中文管理后台

日期：2026-10-27（Asia/Shanghai）。状态：**管理 UI 与真实 Go/SQLite 草稿 API 已完成本地验收；未合并 main、未连接生产、未开放公网后台。**

## 1. 范围与实现

沿用已验收的 P6-A/B 架构和接口，继续 `feat/v1.1-admin-p6a`。管理应用独立位于 `admin/`，使用 Vue 3、TypeScript、Vite 和现有 API，无大型 UI 框架，不将管理依赖加入 V1.0 Nuxt 访客 bundle。本阶段未改 Go 业务代码、数据库 schema、V1.0 前台源码或正式发布脚本。

| 页面                | 已接入的真实操作                                                                             |
| ------------------- | -------------------------------------------------------------------------------------------- |
| `/admin/login`      | challenge/nonce 登录、错误密码、限速反馈、Session 恢复                                       |
| `/admin/`           | 真实草稿项目/精选/分类统计、工作区 revision、中文审计记录；公开统计明确未接入                |
| `/admin/projects`   | 搜索/分类/状态/归档筛选，新增/编辑、技术栈/外链/封面/展示/精选、归档恢复；拖拽与键盘完整排序 |
| `/admin/categories` | 真实新增/编辑、原子排序、引用保护和未引用删除                                                |
| `/admin/media`      | PNG/JPEG/WebP 上传、预检、XHR 进度、私有预览、元数据和公开使用确认、引用保护与未引用软删除   |
| `/admin/profile`    | 品牌/介绍/头像/技术方向/能力/理念/社交/联系/简历草稿，动态字段与素材选择                     |
| `/admin/settings`   | 网站/首页/页脚文案、逐页 SEO、默认/逐页分享图；主域只读，不提供部署配置表单                  |
| `/admin/account`    | 当前密码校验、修改密码，成功后全部旧会话失效并要求重新登录                                   |

项目顺序通过独立完整排序界面保存，项目创建后追加末尾；创建和排序是两次独立操作。项目永久删除、媒体物理清理和图片恢复未实现。资料来源仍保持原有待确认标记，没有虚构项目状态、技术栈、截图、链接或个人履历。

后台采用紫黑/暖白品牌配色、桌面侧栏、手机原生抽屉、统一表单/通知/状态/焦点。窄屏项目表格保留可读列宽，仅在具名、可聚焦区域内横滚，不使整页横向溢出；手机素材单列，桌面素材卡片加宽。

## 2. 认证与并发安全

复用服务端 Argon2id、SQLite Session、Secure/HttpOnly/SameSite Strict Cookie、一次性登录 challenge、CSRF 和限速，没有假登录或公开账户初始化。初始化仍只接受真实 TTY 隐藏密码输入；管理端不保存密码、Session 或 CSRF 到 localStorage/sessionStorage。localStorage 只保存主题。

写请求显式携带原表单 `If-Match`；项目创建使用稳定幂等键。409 时保留输入和原基准，不自动重试；可读取最新内容作对照，必须明确勾选核对后才能重新提交完整对象。排序冲突保留当前顺序，要求重新读取集合。内部跳转、返回、退出与刷新有未保存保护。

401 会话失效时保留已挂载表单，显示重登录遮罩。错误当前密码的明确 `INVALID_CREDENTIALS` 不误清有效 Session，真正 `AUTH_REQUIRED` 仍撤销内存认证。迟到的旧工作区读取不能覆盖最新缓存；请求中的资料/设置表单锁定，避免响应覆盖继续编辑的输入。

客户端统一处理 401/403/409/413/415/422/428/429/503，反馈使用中文。API 与私有图片目的路径限定同源，文本采用 Vue 插值；无 `v-html`、任意执行或抓取网站截图功能。管理 HTML/资源 no-store/noindex，严格 CSP 无 unsafe-inline/eval。服务端验证和草稿事务保持原样，没有为了 UI 通过而关闭安全校验。

## 3. 草稿、图片和发布边界

所有保存只进入私有 SQLite 草稿，不修改 V1.0 HTML、SEO、静态图片或生产数据。表单显示自己的基准 revision，概览显示当前工作区版本；尚无可信的正式发布数量，仪表盘明确显示「发布服务尚未接入」。

发布、私有站点预览、任务执行和历史恢复均禁用并说明 P6-D。后端相关接口仍真实返回 `503 WORKER_UNAVAILABLE`，不存在按钮假报发布成功。侧栏访客网站只是既有前台，不是草稿预览。

图片仅通过已认证 content 接口预览，不把 private contentUrl 当永久公网地址。文件由 Go 重新验证、解码重编码并进入独立持久卷；新素材默认未确认，重复内容保留已有确认状态。项目/头像/分享素材绑定前要求人工公开确认，不能据此推断已经发布。草稿/文档/快照引用保护由服务器执行，软删除不清物理文件。

## 6. 遗留风险与未验证范围

1. 原 Nuxt 构建链 `node-forge@1.4.0` / GHSA-86w9-cpqp-85rv 仍产生 **7 high / 0 critical**。本轮没有确认兼容修复，audit 建议的 Nuxt 4.1.3 为破坏性回退，未执行 force。静态运行镜像不运行 Node 不能消除开发/构建风险；用户未接受该剩余风险，P5 公网门槛继续有效。
2. Go `x/crypto@v0.58.0` 的 GO-2026-5932 指向未维护且无修复的 openpgp；本项目不导入该包，扫描无可达符号/受影响导入包，但模块级记录仍保留。不能声称零风险。
3. 本阶段不提供静态构建 worker、正式草稿站点预览、发布、版本恢复、备份恢复或生产部署。现有容器持久化测试不等于灾难恢复验收。
4. 未执行 OS镜像CVE、峰值/DoS、完整WCAG/读屏、真实移动硬件、Safari/Firefox及Lighthouse。浏览器主要上传PNG；其他格式与攻击输入在Go测试回归，不冒称全组合UI已测。旧图片解除引用后删除的完整UI链仍可扩展测试。
5. Blog/Nav/ERP真实截图/技术栈/状态/链接、更多公开个人资料仍待用户补充；只保留原待确认资料，ERP必须脱敏核验。

## 7. P6-D 实施建议

以已确定 [发布设计](../architecture/V1.1-PUBLISHING.md) 为依据，先完成不可变快照与资源引用锁定，再实现无公网命令入口的受限 worker、可信静态构建/验证和原子激活。明确失败任务与当前公开版本对账，验证HTML、hydration数据、canonical/OG/sitemap同步；保留上一成功内容版本与静态产物，完成构建失败/切换失败/重启恢复及回滚测试后才启用发布按钮。

继续隔离 API、DB、私有图片与公开发布数据；构建不可获得管理员秘密、SSH或GitHub令牌。先在独立测试环境接入 UI 的503区域，不更改V1.0生产。P6-E再做完整备份恢复、多服务升级回退、安全/性能与生产预检。
