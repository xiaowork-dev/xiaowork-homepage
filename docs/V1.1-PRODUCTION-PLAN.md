本轮最终六角色统一运行源码为 `817aa533741bdd5de23f322fa5e5171442cb28a9`、SQLite schema3，实际镜像ID与构建参数见[最终发行组](P6E-FINAL-RELEASE.md)和[镜像清单](evidence/P6E-final-runtime-manifest.json)。[跨源码验收](P6E-CROSS-SOURCE-ACCEPTANCE.md)已在独立本机环境完成旧be5c完整组与最终组的12项主矩阵及4项新内容专项；[容器运行边界](evidence/P6E-final-runtime-boundaries.json)实际复核非root、只读根、最小权限和Worker隔离。以上证据均不代表真实德国服务器或正式域名链路已通过。

## 独立服务边界

1Panel OpenResty沿用host网络（现状来自此前交付，P6-E未重新连接确认），未来只将本站上游从V1.0回环端口切至V1.1专属网关回环端口。V1.0目录、镜像、`.env/.deploy`和容器保留，端口选择须在正式授权后重新只读确认。

```text
Cloudflare HTTPS → 1Panel OpenResty → 127.0.0.1:<独立V1.1端口>
                                      └─ gateway
                                          ├─ /admin/ → Vue静态后台
                                          ├─ /api/admin/v1 → Go API（仅内部网络）
                                          └─ / → publication-static
                                              ├─ current/immutable release
                                              └─ legacy frontend（V1.0旧资源兼容）
Go API → SQLite、私有uploads、只读publications、受限UDS
Worker（默认关闭、network none）→ UDS、只读uploads、publications
```

API、Worker、SQLite、静态服务不映射宿主业务端口。仅gateway绑定127.0.0.1；不存在公开3100/8081等业务端口。控制网络独立、固定gateway来源CIDR，API只信任它写入的HTTPS代理信息。Worker无网络、无SQLite、session secret、SSH/GitHubToken、DockerSocket。静态服务和API仅只读发布卷；所有写入使用独立持久卷。

`deploy/v11/gateway-openresty.conf`仅接受本站Host，默认站点只提供无敏感信息health，其他请求关闭连接。网关到API固定HTTPS语义仅适用于该回环入口受OpenResty独占使用的部署；未来若上游拓扑变化必须复审，不可把它公开到非受信网络。Secure/HttpOnly/Strict Cookie、CSRF、精确Origin和管理员鉴权继续由Go服务执行。

## 正式配置与缓存

- OpenResty的本站专属server中保留实际Host，代理到新回环端口；不覆盖其他站点、全局配置或证书。
- TLS证书必须覆盖根域名，Cloudflare Full(strict)，禁止Flexible，HTTP→HTTPS只在确定的入口跳转，验证无循环。
- `/admin`、`/admin/*`、`/api/admin/v1*`、私有预览的全部HTML/JS/CSS/图片禁止Cloudflare/CDN缓存；透传no-store/noindex、Cookie，不能用noindex替代鉴权。
- 公开HTML、release marker、robots、sitemap使用no-store；`/_releases/<id>/_nuxt|assets/`按不可变内容缓存。不能给全站套“缓存所有内容”。
- 私有uploads、SQLite、snapshots、staging、intent/receipt、manifest不能有公开目录映射。
- 使用仅影响本站的OpenResty访问限制或Cloudflare Access作为额外防护；不替代管理员身份认证，也不修改整机80/443白名单影响其他网站。源站Host/SNI绕过剩余风险必须实测并列出。

当前Go API明确拒绝正式管理origin开启 `XIAOWORK_LOCAL_PUBLISH`，V1.1部署工具也禁止openresty拓扑开启该测试开关。当前实现尚无正式origin可启用的生产发布gate；须另行设计、实现、验收并取得授权。不能将localhost、测试origin或本地开关用于生产来绕过该门槛。

完整源码最终镜像组的 [本地生产计划渲染预检](evidence/P6E-final-production-preflight.json) 已核对六角色精确镜像、正式origin固定、发布gate关闭、Worker默认关闭且无网络/数据库/凭据/Docker Socket及容器安全边界。仅执行Compose配置渲染，没有启动或检查真实OpenResty。预检中的 `13210` 是本机示例回环端口，尚未确认可在正式服务器使用。

## V1.0→V1.1 切换顺序

1. 获得正式部署授权；只读核实主机、端口、现有本站OpenResty配置、证书、Cloudflare规则及其他站点健康基线。
2. 保存本站反代与V1.0镜像/源码/目录/回环端口记录。创建新V1.1目录，不覆盖V1.0或旧 `.deploy`。
3. 拉取完整已验收GitSHA及六角色固定镜像描述符；独立卷初始化或按已验收迁移导入真实内容；TTY创建管理员，不传密码参数或环境变量。现有升级仅验收schema3；跨schema自动迁移/降级未实现，schema变化须先补兼容策略与独立测试，不能用旧镜像直接回退数据库。
4. 使用 `openresty`拓扑、Worker和正式发布gate关闭，启动V1.1独立栈；HTTP内部三页、管理可信HTTPS、私有资源鉴权、数据/图片/SEO/备份恢复验收。
5. 核对明确占位、Blog/Nav/ERP真实资料及ERP脱敏授权。只有用户确认的发布范围可公开。
6. P6-E关键故障恢复、完整离线备份恢复、代码更新/回退、安全和浏览器门槛全部通过后，仍需完成正式origin发布gate的独立安全设计、实现和验收，并取得用户最终内容范围、剩余风险及上线授权；当前关闭的gate不属于可以直接开启的现成功能。
7. 维护窗口备份本站配置和V1.1完整数据。只改本站OpenResty上游并验证语法/reload，不重装OpenResty，不触碰其他站点。
8. 核验正式HTTPS三页、管理员会话/CSRF、真实后台JS/CSS、旧标签资源、SEO、robots/sitemap、favicon、Cloudflare和源站保护，以及其他站点基线。只有第6步正式发布gate通过并获授权后，才在生产执行预览/发布/恢复验收；不能复制本地开关进行测试。上线探针须核对当前manifest全部HTTP文件大小与SHA，而非只接受200或healthy。

切换仅更换本站上游但网关容器重建可能有短暂失败。若失败，停止进一步变更，将本站上游恢复V1.0记录并核验旧站；V1.1新卷保留供排查，不自动恢复/删除/降级数据库。P6-E不执行这些真实服务器操作。

后续V1.1代码更新需按[更新与代码回退说明](V1.1-RELEASE-OPERATIONS.md)停写、备份并由新旧维护器核验完整数据；未知写入者或恢复状态必须保留操作锁，先人工对账。代码回退切换镜像但保留现有数据库；内容恢复只切换兼容静态release且保留草稿；数据库灾难恢复必须使用完整备份还原到独立空卷，会回到备份时点。旧备份须配套其bundle记录的旧maintenance镜像，不能用新维护器省略字段或跳校验。容器更新和显式恢复均可能有短暂停机，不承诺零停机。

## 必须保留的上线门槛

关键真实故障场景、数据库/媒体/历史发布独立恢复、代码更新与回退、镜像OS扫描、后台鉴权/上传/路径安全、浏览器和性能证据未通过时，不能声明具备正式发布条件。npm/Go零高危不等于系统零风险。生产旧镜像未更新，V1.0原安全接受与公网入口门槛继续独立有效。

正式服务器Node/Docker/Compose版本、选用端口、访问限制、日志保留、发布维护窗口及最终内容范围需要在另行授权的只读预检后确认。加密异地副本、密钥保管、RPO/RTO、保留与容量告警方案见[备份运维说明](V1.1-BACKUP-OPERATIONS.md)；尚未确认外部存储、告警账户和接收责任人，不能把方案视为已配置运行。
