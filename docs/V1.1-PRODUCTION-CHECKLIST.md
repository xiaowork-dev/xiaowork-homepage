# V1.1 正式发布检查清单

更新：2026-10-28。**当前只允许隔离验证，不能据此直接上线。** 正式域名固定 `https://xiaoworks.com`，默认 Worker 与正式发布 gate 保持关闭；本文件不修改 1Panel、OpenResty、Cloudflare 或生产数据。

## 必须通过的工程门槛

- [x] 冻结be5c基线十二项真实故障安全行为、状态对账、恢复失败阻断均实际验证。恢复成功后旧诊断缺陷保留于原证据，后继源码另修复和专项验证；不等同最终发行全栈验收。
- [x] 备份使用停写加 SQLite VACUUM INTO，验证 WAL、schema、哈希、图片与历史资源引用；备份源只读挂载短回归通过。
- [x] 在独立空卷恢复并启动后，真实验证账户、草稿、媒体、历史、active 与公开页面；保留所有原卷。
- [x] V1.1 专用同源码/同schema镜像更新、回退、坏候选恢复、schema拒绝及独占锁通过；停止候选失败与恢复记录ENOSPC保守阻断专项通过。
- [ ] 不同功能源码版本升级和回退兼容验收；不能以同源码镜像重封装代替。跨schema迁移未实现，仍必须拒绝。
- [ ] 后继源码完整六角色最终镜像组装、扫描和端到端回归；单API候选专项不替代此门槛。
- [ ] 崩溃残留current.next链接经受信操作者可审计处理并通过备份/更新恢复验收，不能跳过完整性检查。
- [ ] 最终完整 Git SHA、各运行镜像 ID/digest、数据库 schema 和 manifest 已记录，分支正常推送并远端核验。
- [ ] 所有最终镜像完成 OS/包 CVE 扫描；high/critical 解决或由用户明确接受剩余风险；未知级别及来源冲突也有处置记录。
- [x] 本地私有预览全部资源认证、退出和过期拒绝；管理界面/API no-store/noindex；活动静态产物秘密扫描通过（`P6E-publishing-browser.json`、`P6E-security-http.json`、`P6E-public-secret-scan.json`）。生产切换后仍须重验。
- [x] 上传、派生、预览、构建、独立 HTTP 核验上限一致；资源限制、磁盘警告、并发互斥已验证。没有全局配额或磁盘预留保证。
- [x] 最终 Chromium 回归覆盖主要管理操作、旧A标签→B→刷新→恢复A、五档宽度、深浅主题；Firefox/WebKit 补测范围与未通过的 TLS 部分单独记录，不能扩写为完整跨浏览器管理验收。
- [x] Lighthouse 对真实本地静态版本完成6次实测：首页mobile三次中位95/LCP1123.47ms/CLS0/TBT195.31ms。无真实交互样本，不冒称 INP 或真实用户核心指标通过；CPU警告和测试内容限制保留于证据。

## 生产拓扑预检（部署授权后执行）

- [ ] 准确识别德国 `xiaowork-main`，先只读核对 V1.0 当前版本、独立目录、端口、资源和 1Panel OpenResty host 网络状态。
- [ ] 保留 V1.0 容器、镜像、`.env/.deploy` 和原本站 OpenResty 配置备份；不删除或覆盖无关服务。
- [ ] 新 V1.1 目录、Compose project、数据库/图片/发布/秘密卷与 V1.0 完全隔离；API/Worker 不映射公网端口。
- [ ] 网关仅绑定已核对空闲的 `127.0.0.1` 端口；OpenResty 单独转发本站的 `/`、`/admin/`、`/api/admin/v1/`，不得回落到 Nuxt SPA 假成功。
- [ ] HTTPS 代理链路、Host、X-Forwarded-Proto 和受信代理 CIDR 与实际拓扑一致；Secure/HttpOnly/SameSite Cookie 不放宽。
- [ ] 所有 HTML、管理/API/预览路径绕过 Cloudflare 缓存，只有版本化公开资源可 immutable 缓存。仅改本站规则，不改变整个 zone 的其他业务。
- [ ] Full (strict)、根域证书、HTTP→HTTPS、源站防绕过按本站范围验证，不改全机80/443白名单影响其他站。
- [ ] 如生产正式发布 gate 尚未满足安全验收，保持关闭并停止操作；禁止借 V1.1 绕过原风险门槛。

## 上线内容与操作确认

- [ ] 用户确认首版允许哪些明确占位项目和品牌文案；未提供真实截图、技术栈、状态、URL 继续明确待确认。
- [ ] ERP 公开截图经用户确认无敏感业务信息；不把隔离验收合成图迁入正式数据。
- [ ] 管理员在安全 TTY 初始化，密码不通过 argv/env/仓库传递；备份按含账户敏感数据保护。
- [ ] 用户明确批准本次生产部署时间、预计管理端停写窗口、备份位置与回退责任。
- [ ] 切换先验证新栈内网健康及静态内容，再仅切本站上游；异常时最小范围恢复旧入口，不回退不兼容 schema。
- [ ] 上线后复核首页/项目/关于、管理认证/CSRF/发布、SEO、媒体、浏览器及其他已有网站不受影响。

内容恢复仅切静态 active；代码回退切服务镜像；数据库灾难恢复恢复独立备份。这三种操作不得混用，内容恢复不应删除当前草稿或恢复旧账户/schema。
