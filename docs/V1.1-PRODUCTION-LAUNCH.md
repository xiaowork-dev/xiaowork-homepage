# V1.1 正式上线操作手册

适用版本：运行镜像与宿主工具都是 `c81af02da2c40104804cba33fd0146de3dd0980b`（2026-11-09 完整验收通过）。脚本位于 [`deploy/v11-production/`](../deploy/v11-production/)，由 `scripts/v11-production-scripts.test.mjs` 做静态检查。

## 0. 原则

- V1.0 容器（`xiaowork-homepage-web-1`，`127.0.0.1:3100`）全程保留，上线后作为回退目标，不停止、不删除。
- V1.1 只绑定回环地址：HTTP `127.0.0.1:3110`；固定网段 `192.168.240.0/28`，edge 网段为 `.16/28`。
- 正式发布 gate 默认关闭。上线时公开站点由 frontend 镜像提供与 V1.0 相同的内容；以后需要从后台发布时，按第 6 节另行授权。
- 切换只改动 `/opt/1panel/www/sites/xiaoworks.com/proxy/root.conf` 中的一行 `proxy_pass`，然后重载 OpenResty。改之前先把原文件保存到 `/opt/xiaowork-homepage-v11/release/`。
- 不执行任何全局清理，不删除旧镜像、数据卷或备份。

## 1. 部署影子实例（不影响线上）

在服务器上以 root 执行。脚本会做以下事情：

- 预检：目录、端口或同名容器已存在时直接拒绝。
- 在 `/opt/xiaowork-homepage-v11/` 下建立 `.tools/node`（官方包，先按官方 SHASUMS256 校验）、`app/`（检出 c81af02 的工具代码）、`release/`、`backups/` 和 `logs/`。
- 用已验收的发行描述符，以 openresty 拓扑部署项目 `xiaowork-homepage-v11-prod`（生命周期工具要求项目名带后缀）。

```bash
bash deploy/v11-production/prod-setup.sh
```

## 2. 创建管理员（必须本人在终端输入）

管理员密码只能通过交互式终端输入，不接受命令参数、环境变量或管道。由你本人在终端里执行，自己设置用户名和密码：

```bash
ssh -t xiaowork-main docker exec -it xiaowork-homepage-v11-prod-api-1 /homepage-api init-admin
```

然后导入 V1.0 的现有内容（3 个项目、3 个分类、品牌资料和站点文案）：

```bash
ssh xiaowork-main docker exec xiaowork-homepage-v11-prod-api-1 /homepage-api import-v1
```

## 3. 上线前核对

- 逐页比对 V1.0 和 V1.1 的公开内容：`python3 deploy/v11-production/compare-v10-v11.py`，期望输出 `CONTENT_IDENTICAL`。
- 通过 `Host: xiaoworks.com` 访问 `127.0.0.1:3110`：`/admin/` 应返回 200，`/api/admin/v1/auth/session` 应返回 401。
- 执行一次 `v11-release.mjs status`，并做一次手动备份（见第 4 节），确认备份链路正常。

## 4. 每日本地备份

```bash
install -m 700 -D deploy/v11-production/v11-backup.sh /opt/xiaowork-homepage-v11/bin/v11-backup.sh
install -m 644 deploy/v11-production/xiaowork-homepage-v11-backup.service deploy/v11-production/xiaowork-homepage-v11-backup.timer /etc/systemd/system/
systemctl daemon-reload
systemctl start xiaowork-homepage-v11-backup.service   # 立即试跑一次
tail -1 /opt/xiaowork-homepage-v11/logs/backup-status.log
systemctl enable --now xiaowork-homepage-v11-backup.timer
```

- 执行时间：每天 UTC 19:30（北京时间 03:30）。备份期间管理端会短暂停写，公开页面不受影响。
- 不自动删除旧备份；磁盘可用空间低于 2 GiB 时拒绝执行，并在 `backup-status.log` 中记录 `REFUSED`。
- **风险**：备份如果中途被强杀，按设计会保留锁，管理端会保持停写，直到运维人员处理（见故障注入 B3）。目前还没有告警通道，需要定期查看 `backup-status.log`。
- **异地副本**：用户已决定上线后再补，目前只有本机备份，不能抵御整台服务器丢失。

## 5. 切换与回退（需要用户最终确认）

```bash
bash deploy/v11-production/cutover.sh       # 切换到 V1.1
bash deploy/v11-production/rollback-v10.sh  # 随时切回 V1.0
```

`cutover.sh` 的行为：

1. 只有当前上游确实是 `127.0.0.1:3100`、并且 V1.1 在 3110 正常响应时才会执行。
2. 先保存原配置，然后替换 `proxy_pass` 这一行，执行 `openresty -t` 检查配置，再重载。
3. 用正式域名核验 `/`、`/projects/`、`/about/`、`/robots.txt`、`/sitemap.xml`、`/admin/` 都返回 200，会话接口返回 401。
4. 任一步失败都会自动恢复原配置并重载，即自动切回 V1.0。

切换时 OpenResty 只是平滑重载，没有停机窗口；同机其他站点不受影响。

## 6. 上线后（可选，需另行授权）

- 后台发布：先执行 `v11-release.mjs backup`，再执行 `authorize-publishing`，授权有效期 7 天。之后才能在后台预览和发布。
- 异地加密副本、告警通道：按 [备份运维](V1.1-BACKUP-OPERATIONS.md) 另行落地。
