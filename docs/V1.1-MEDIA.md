# V1.1 私有图片与媒体管理

> P6-B 本地实现说明。媒体保存只更新私有草稿，不代表预览生成、正式发布或生产部署完成。管理页面、发布 worker、资源 GC 和生产持久化恢复分别在后续阶段验收。

## 接口与权限

所有路径以 `/api/admin/v1` 为前缀。真实会话认证由统一 guard 执行；写请求还要求准确的 HTTPS Origin、会话 CSRF 和工作区 `If-Match: "ws-N"`。写入通过共用事务同时更新媒体、工作区版本、变更记录和审计；处理图片期间版本发生变化时，最终事务返回 409，不覆盖其他编辑。

| 路径                      | 行为                                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `GET /media`              | 上传派生图列表，支持 `limit` 1～100（默认 20）、不透明 `cursor`、`status=active/deleted/all`（默认 active） |
| `POST /media`             | 单文件 multipart，仅接受名为 `file` 的一个文件，不接受额外表单字段                                          |
| `GET /media/{id}`         | 私有媒体元数据与项目草稿、文档草稿、历史快照引用数量                                                        |
| `PATCH /media/{id}`       | 仅修改 `alt`、`displayName`、`publicUseConfirmed`、`publicConfirmationNote`；不修改图片字节                 |
| `GET /media/{id}/content` | 认证读取、核对文件大小与 SHA-256 后返回净化派生图；已软删除对象不可读取                                     |
| `DELETE /media/{id}`      | 无引用时软删除；仍被引用返回 `409 MEDIA_REFERENCED`，不删除文件                                             |

响应不包含磁盘路径或原始文件名路径。元数据包含服务端 ID、SHA-256、输出 MIME、尺寸、字节数、alt、显示名称、公开确认记录、UTC 时间和引用摘要。所有响应使用 `no-store`、`nosniff` 与统一管理端禁止索引策略。

PATCH 不接受未知字段、重复 JSON 键或字段 null。显示名称最多 160 个 Unicode 码点、alt 最多 500、确认备注最多 2,000；不接收 HTML 或控制字符，备注允许换行和制表符。公开确认的操作者与时间由已认证会话和服务端生成，不能由客户端指定。

上传成功默认 `publicUseConfirmed=false`。图片能被解码不表示它是真实项目截图，也不表示已取得公开权限；ERP 图片仍需管理员确认不含敏感信息。新增媒体不会自动替换任何项目封面，更不会自动发布。

## 实际处理限制

| 项目                 | 限制                                                                         |
| -------------------- | ---------------------------------------------------------------------------- |
| 原图格式             | PNG、JPEG、WebP；扩展名、上传 MIME 和解码识别格式必须一致                    |
| 原文件大小           | 最多 10 MiB，即 10,485,760 字节                                              |
| multipart 请求总大小 | 最多 11 MiB，含头部及其他请求字节                                            |
| 图片单边             | 最多 8,192 像素                                                              |
| 图片总像素           | 最多 25,000,000，先做除法检查以避免乘法溢出                                  |
| 解码并发             | 每个 API 实例最多 1 个，无等待队列；繁忙时返回 429 和 Retry-After            |
| 派生文件大小         | 最多 32 MiB，由编码输出 writer 实际限长                                      |
| 输出格式             | JPEG 输入重新编码为质量 90 的 JPEG；PNG、WebP 输入重新编码为 PNG，保留透明度 |

拒绝 SVG、GIF、AVIF、HTML、PDF、压缩包、动画 WebP、多文件、远程 URL 抓取及路径型文件名。AVIF 上传尚未实现，不能将可信仓库 AVIF 资源的兼容性写成开放上传支持。

处理顺序是认证/CSRF、工作区版本、并发闸门、私有临时文件限长、`DecodeConfig` 尺寸校验、真实解码、重新编码、内容哈希、持久化、工作区事务。扩展 WebP 另外检查 RIFF 边界和实际 VP8/VP8L 帧尺寸，拒绝用较小 VP8X canvas 隐藏大帧的输入。使用 Go 标准 PNG/JPEG 编解码器及显式锁定的 `golang.org/x/image/webp` 解码器，不声称 Go 标准库提供 WebP 编码。

输出由解码后的像素重新生成，不复制 EXIF、GPS、注释或原始附件。原件仅在请求期间保留于私有临时目录，处理结束即清理；不会作为公开或认证下载接口的返回内容。当前实现不提供 EXIF 方向校正或专业 ICC 色彩管理，摄影素材应在上传前确认显示效果；截图及透明像素的标准 RGB 处理有真实测试。

## 私有存储与不可变字节

`UploadDir` 必须是独立持久化私有目录，不能放入 `public/` 或公开 Nginx 根目录。Linux 根目录要求仅服务身份可访问，目录使用 0700，文件使用 0600；Windows 开发环境仍须依赖用户目录 ACL，不将 Unix mode 检查宣称为 Windows 权限审计。

布局为 `tmp/<服务端随机名>` 与 `derived/<SHA-256>.png|jpg`。客户端文件名只可成为受限显示名称，不参与磁盘路径。使用 Go `os.Root` 约束文件系统边界，拒绝内容路径中的软链接、遍历和异常扩展名。

净化结果先写入新的私有临时文件并 fsync；同卷无覆盖硬链接将完整文件原子登记到哈希路径，随后清理临时名称。Linux 还同步派生目录。这里的硬链接仅用于私有临时文件的原子创建；未来发布到版本资源树仍必须复制文件，不能将可写私有存储与发布资源共享 inode。

相同派生字节复用已有对象，并重新核对实际文件 SHA-256 与大小；不会静默覆盖已有哈希路径。相同内容已有软删除记录时返回 409，避免隐式恢复。文件缺失、损坏、非普通文件或哈希不符时读取、去重和公开确认均失败，不返回假成功，不以占位图掩盖私有存储损坏。

磁盘与 SQLite 不具备跨资源原子事务。图片已持久化而数据库版本冲突、会话失效或事务失败时，可能留下无数据库引用的孤儿派生文件。此时保守保留，不删除可能被其他对象复用的字节；不在 HTTP 请求里执行 GC。请求取消会阻止后续登记，但不能保证 Go 解码器内部计算会立即中断。

## 引用与占位资源

软删除同时检查项目草稿、站点/个人资料草稿和不可变快照引用，SQL 触发器提供第二道约束。隐藏或归档项目仍属于草稿引用；快照引用覆盖后续任务、保留预览、历史发布和回滚所依赖的媒体。删除新草稿引用并不等于撤回已公开历史资源。

可信仓库资源使用 `storage_kind=builtin`，通过显式导入的白名单与文件哈希登记。Blog/Nav/ERP 原有占位 SVG 继续标识为占位，导入确认只表示其属于既有受控仓库资源，不表示真实项目已验证或截图已接入。builtin 不经过开放上传接口，也不由本媒体列表/内容接口读取或修改；项目引用需显式使用 `{"kind":"builtin","id":"..."}`。

上传派生图使用 `{"kind":"media","id":"..."}` 引用。客户端不能提交任意本地路径、URL、MIME 或哈希作为封面替代。公开静态站仍保留已有故障占位机制；新增私有媒体必须经后续快照适配、发布复制和真实页面验证后才能进入访客页面。

## 验证范围与后续运维

媒体测试覆盖真实 PNG/JPEG 重新编码与注释清除、真实 WebP 转换与透明度、格式伪造、尺寸头部超限、原文件限长、WebP canvas/帧尺寸不一致、原子去重、坏哈希拒绝、路径、HTTPS 会话与 CSRF、版本冲突、并发拒绝与恢复、三类引用保护以及软删除后的不可读状态。Windows 本机不能创建软链接时不能将该分支写成已通过；本轮已在 Linux 隔离容器补齐 POSIX 权限与软链接分支，最终全包 48 项通过、0 跳过，见 [Go 证据](evidence/P6B-go-tests.txt)。[Docker 重建持久化](evidence/P6B-docker-persistence.txt) 也已实际通过；生产挂载权限、完整恢复或峰值资源测试不能由这些结果代替。

后续部署须将 SQLite、私有派生图和服务秘密分别持久化并备份；恢复时核对数据库引用与实际文件哈希。需为媒体总磁盘用量设置部署配额、磁盘容量告警，并在容器中实测 25M 像素图片的 CPU/内存峰值。首次 GC 只允许经过人工审查的 dry-run 清单，至少 30 天宽限，还需检查 manifest、任务与备份；当前没有自动 GC 或任意路径删除接口。
