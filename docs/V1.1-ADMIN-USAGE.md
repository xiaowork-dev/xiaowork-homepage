# XiaoWork V1.1 管理操作说明（P6-C）

本文说明当前中文管理 UI 与 Go API 的操作方式，不替代阶段验收报告。浏览器覆盖范围、截图、测试是否通过，以对应交付文档和实际证据为准。本文没有宣称生产部署、公开发布、备份恢复或 P6-D 功能已经完成。

## 1. 入口、账户和 HTTPS

默认本地管理入口为 `https://localhost:3443/admin/`，来自 `compose.admin-dev.yaml`。先按[开发环境说明](V1.1-DEVELOPMENT.md)启动独立环境，核实本项目的公开 CA 证书，在受控浏览器中建立正确的证书信任。不要忽略证书错误、关闭 TLS 验证或改用 HTTP 登录。实际端口或 origin 调整后，必须同步精确认证配置。

首次管理员只能通过受控交互终端创建：

```bash
docker compose -f compose.admin-dev.yaml exec -it api /homepage-api init-admin
docker compose -f compose.admin-dev.yaml exec -T api /homepage-api import-v1
```

没有默认账户、默认密码、公开注册或网页初始化入口。已有管理员时拒绝覆盖；一次性导入重复执行不会覆盖后来编辑的草稿。忘记密码时可由受权操作者使用 TTY `reset-admin`，具体限制见 [API 使用说明](V1.1-API-USAGE.md)。不要把密码放进命令参数、环境变量或仓库。

登录页填写「管理员账户」「密码」，可切换密码显示。错误或限速会显示服务端提示；出现等待时间时，等待后再手动操作，不连续重复提交。会话通过受保护 Cookie 发送；页面不把会话或 CSRF 写入本地存储。

「修改密码」要求当前密码、两遍新密码。新密码为 12～128 个 Unicode 字符、UTF-8 最多 1,024 字节，不自动去除空格。成功后撤销全部旧会话，当前页面重新登录。其他标签页也需要重新验证身份。

## 2. 草稿与公开网站的区别

当前菜单包括工作区概览、项目管理、项目分类、图片资源、品牌与个人资料、网站与 SEO，以及修改密码。所有内容保存进入私有草稿和变更记录，不会立即改写 V1.0 的公开 HTML、SEO 或图片。

概览中的数字是草稿统计。「公开版本」「已发布项目」和草稿差异在 worker 接入前没有可信发布结果，不应从草稿数量推断网站已经更新。「预览 · P6-D」「发布 · P6-D」「历史恢复 · P6-D」明确禁用；后台 API 的相应功能目前返回 worker 不可用，不能通过刷新或修改数据库完成发布。

侧栏「查看访客网站」打开现有静态前台，不是当前私有草稿的预览。正式内容 origin 固定为 `https://xiaoworks.com`，不代表本轮已将管理功能部署到该域名。

## 3. 项目管理

项目列表支持名称、slug、简介和技术栈搜索，以及分类、状态、归档筛选。「清除筛选」会显示全部项目，包括已归档项。筛选只影响当前列表，不改变草稿。

选择「新增项目」或某行「编辑」，填写：

- 名称、slug、分类、状态、简介和纯文本详情。
- 技术栈：每行或逗号分隔，最多 20 项，每项最多 40 字，不重复。
- 已确认的公开 HTTPS 官网、源码地址；未确认时留空。
- 列表展示、首页精选、资料是否仍含占位。
- 项目封面、封面类型和替代文本。

新项目默认隐藏、非精选、状态待确认、资料含占位，技术栈和外链为空。已有 Blog、Nav、ERP 的未知资料不应凭推测改为已上线、真实截图或真实技术栈。填写非待确认状态、技术栈、外链或真实截图时，界面要求勾选事实核验；这仍是管理员声明，不是服务端对外部项目的自动验证。

封面可保留仓库内置占位资源，也可选择已核实可公开的上传素材。内置封面不能标为真实截图。仅更换图片不会自动取消「资料含占位」，也不会把项目状态改为已上线。替代文本应描述画面与真实性；不要将受保护的 `/api/admin/v1/media/.../content` 当作项目官网或公开图片地址粘贴。

点击「保存项目草稿」完成本项目内容操作。新项目追加到末尾；创建与排序是两次独立操作，不能视为一个事务。创建意图使用幂等键减少重复提交；超时仍须先读取列表核对实际结果。

「归档」需要再次确认，归档会隐藏项目并保留内容、媒体及历史。切换到已归档或全部项目后可「恢复」；恢复后仍需核查展示状态，不会自动公开发布。本阶段没有永久删除项目按钮。

## 4. 分类与完整排序

分类创建时设置名称与稳定 slug；创建后只能修改名称，slug 不能变更。已有项目（包括归档项目）引用的分类不可删除，界面显示引用数量并禁用删除，服务端也再次校验。未引用分类删除前需要确认。

项目「调整项目顺序」列出全部未归档项目，与搜索或筛选结果无关；分类「调整分类顺序」列出全部分类。两者均支持拖动和「上移」「下移」键盘按钮，最后点击「保存完整排序」。服务端一次接收完整 ID 集合，在单个事务内保存顺序，不通过项目 PUT 直接写 order。

排序界面尚未保存的移动不会改变服务端。版本冲突时顺序保留，不自动重试；选择「重新加载」会放弃当前移动，读取完整新集合后再调整。

## 5. 上传与私有素材

在「图片资源」的「选择上传图片」中点选一张文件，也可拖入上传区域。每次上传一张，支持静态 PNG、JPEG、WebP：

| 限制       | 当前行为                                                                    |
| ---------- | --------------------------------------------------------------------------- |
| 原图大小   | 大于 0，最多 10 MiB                                                         |
| 图片尺寸   | 单边最多 8,192 px，总像素最多 2,500 万                                      |
| 不支持上传 | SVG、GIF、AVIF、损坏或声明格式不一致的文件                                  |
| 处理       | 浏览器预检后，服务端重新校验并解码重编码；JPEG 输出 JPEG，PNG/WebP 输出 PNG |
| 存储       | 独立私有持久卷，逻辑素材 ID，不返回服务器文件路径                           |

浏览器预检通过不等于服务端已经接受。点击「上传到私有素材库」后显示 XHR 传输进度；文件发送完毕还需等待服务端处理结果。上传错误、超限、格式不支持或版本冲突会明确显示，不包装为成功。

新素材默认没有公开使用确认。上传相同内容时会复用已有素材及元数据，不覆盖原说明，也不会强制撤销已有公开确认。上传完成后打开素材信息，可编辑显示名称、替代文本与核验说明。

私有预览需要登录，使用同源受认证接口；它不是可对外分享的永久图片地址。预览加载失败时可点「重新加载预览」，并检查会话是否失效。服务端重编码可去除文件附带元数据，但不会替你识别画面中的客户名称、账户、权限、订单等敏感内容。

确认用途后，填写「公开使用核验说明」，勾选「我已核实此图片可公开使用，且不含敏感数据。」，再点「保存素材信息」。ERP 截图尤其需要确认画面已脱敏。此确认只是管理员的内容声明，不代表图片已经发布。

## 6. 将图片绑定或替换到内容

1. 先在素材库完成上传、人工核验和公开确认。若其他页面有未保存表单，先保存或按提示决定是否放弃后再离开。
2. 打开项目、品牌资料或 SEO 设置的图片选择器。选择器只列出未删除且已确认可公开的上传素材；项目还可选明确标记的内置占位封面。
3. 在目标素材卡片点「选择此素材」，再保存所属项目或资料表单。选择器本身只改变当前表单，不会单独保存该引用。
4. 更换封面时选择新素材，再保存项目。品牌图、头像、分享图的可选引用也可通过「清除选择」移除，保存所属表单后生效。仓库内置品牌/分享图引用可以原样保留。
5. 回到素材库重新加载引用数量，核对旧素材是否仍被项目、个人资料/设置或历史快照引用。不要为删除旧图修改数据库或运行全局清理。

有引用的素材不能删除：界面禁用按钮，服务端也返回引用保护错误。无引用素材可点「软删除」，再次点击「确认软删除素材」。软删除保留物理文件、数据库记录和审计；本阶段没有图片恢复、物理删除或垃圾回收功能。筛选「已软删除」可查看记录，不能继续预览已删除图片。

## 7. 品牌资料与网站设置

「品牌与个人资料」管理名称、角色、首页介绍、技术方向和标签、公开 GitHub、头像、品牌图片、品牌与个人介绍、能力组、开发理念、公开联系方式及可选简历。未知履历和未确认联系方式可以留空，不从 Git 提交邮箱推断公开联系资料。

「网站与 SEO」管理站点标题、描述、默认 SEO、默认分享图、首页介绍、页脚、公开社交链接，以及首页/项目页/关于页的标题、描述、分享图。逐页可选字段允许留空；静态渲染时的默认值回退由 P6-D 发布流程接入。当前保存的仍是草稿，不修改公开 canonical、sitemap 或 HTML。

两处首页介绍实际共用同一份草稿内容；不同标签页编辑会受工作区 revision 冲突保护。网站 origin 只读，页面没有服务器、端口、目录、命令、Cloudflare 或部署环境变量编辑器。

## 8. 未保存输入、会话恢复和版本冲突

内部导航、浏览器返回和退出会检查未保存修改；刷新或关闭页面由浏览器提供未保存提示。浏览器可能限制离开提示的显示条件。未保存输入只在当前页面内存中，不是跨刷新自动恢复草稿。明确标记「放弃」的按钮会丢弃对应输入；不需要保存的表单可主动放弃。

会话失效时，重新登录对话框保留后面的当前页面和输入。身份恢复后读取真实工作区版本，但不会把表单原 revision 自动改成新值。版本已变化时应先核对冲突；不要因重新登录成功就认为保存基准仍然有效。

收到 `409 REVISION_CONFLICT` 后没有自动重试：

- **放弃输入，载入最新值**：明确丢弃本表单并读取服务端内容。
- **保留输入，读取最新基准作对照**：保留当前字段，展示最新内容；核对后通过明确确认再提交。完整项目/资料 PUT 会替换该对象的可编辑字段，需要核对其他操作者的改动。
- **排序冲突**：保留当前排序供参考，重新加载完整列表后重新调整。
- **上传冲突**：所选文件保留，读取最新上传基准并勾选确认后再手动提交。

重复 slug、被引用分类/图片等也可能返回 409，需处理具体原因，不能通过反复重试绕过。`401` 要重新登录；`403` 检查身份/来源安全状态；`413/415/422` 按文件或字段提示修改；`428` 重新读取有效版本；`429` 等待提示的时间后手动操作。

请求超时或网络中断不证明操作失败。先重新读取项目/素材列表确认实际状态，再决定重试，避免重复创建。界面会区分「保存成功但列表刷新失败」与保存请求失败。

## 9. 运行边界与后续工作

管理界面为独立静态 bundle，本地 API 不运行任意项目命令；素材和数据库不进入访客静态根。主题偏好单独持久化，身份凭据不写入浏览器 localStorage。

本阶段没有静态构建 worker、私有草稿站点预览、发布、历史版本切换、完整备份恢复验收或 V1.1 生产部署。不要使用 V1.0 `release.sh` 等脚本将本功能分支直接部署到生产，也不要通过删除持久卷解决登录、迁移或证书问题。

已有上游安全告警与 V1.0 公网发布限制继续按安全报告处理；管理 UI 的出现不解除相关发布门槛。操作完成后可退出登录，关闭环境时仅停止本项目并保留卷，不执行全局 Docker 清理。
