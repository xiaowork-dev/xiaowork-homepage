# V1.1 独立开发环境（P6-C / P6-D）

更新：2026-10-27。P6-C 日常环境沿用 P6-A/B 的 Compose 项目和独立数据卷，提供 Vue 3 + TypeScript 管理界面与认证、草稿、图片 API。P6-D 另用 `compose.admin-publish.yaml` 提供显式启用的本地静态 worker、私有预览、全站发布和历史恢复；不原地改造 P6-C 环境。V1.0 生产发布门槛保持独立，管理界面和本地发布均不因此开放生产后台。本说明列出操作方法，不宣称本轮端到端测试已经通过。

## 启动与可信 HTTPS

要求 Docker Linux Engine / Compose。先检查回环 3210、3443 空闲，以及 Docker/宿主路由没有占用 `192.168.247.0/28`。冲突时只调整本项目 override 的 control IPAM、gateway/API/api-init 地址和可信代理 CIDR，不能删除其他网络。

```bash
docker compose -f compose.admin-dev.yaml config --quiet
docker compose -f compose.admin-dev.yaml up -d --build --wait --wait-timeout 120
docker compose -f compose.admin-dev.yaml ps -a
docker compose -f compose.admin-dev.yaml exec -T api /homepage-api info
```

- `http://127.0.0.1:3210`：未改变的 V1.0 前台；HTTP 管理 API 返回 426，绝不创建降级会话。
- `https://localhost:3443`：本地 HTTPS 前台与 API；`/admin/` 为真实管理应用，未登录时进入登录页。
- `/dev-health/api`：仅本地诊断，返回 `data.stage=p6b-api`。
- 默认认证 origin 精确为 `https://localhost:3443`，使用 `https://127.0.0.1:3443` 浏览前台仍可验证证书，但不能将另一 origin 作为管理写请求来源。

`prepare-dev` 是 api-init 的显式命令：检查所有已应用迁移 checksum，追加升级 schema；缺少时生成 32 字节随机 HMAC secret 和专用本地 CA/leaf。它不创建账户、不导入业务内容、不更新既有密钥。部分、过期、损坏或 Linux 权限过宽的 TLS 文件导致失败，需要显式恢复/续签；不通过删除数据卷修复。

CA 私钥仅 api-init 挂载；常驻 API 只有只读 session secret，gateway 只有只读 leaf。先导出**公开证书**，不要导出 key：

```bash
mkdir -p .cache
docker cp xiaowork-homepage-v11-dev-api-init-1:/authority/ca.crt .cache/v11-dev-ca.crt
# Bash，客户端显式信任该 CA，仍验证证书链、主机名和有效期
NODE_EXTRA_CA_CERTS="$PWD/.cache/v11-dev-ca.crt" node scripts/admin-api-smoke.mjs verify
```

PowerShell：`$env:NODE_EXTRA_CA_CERTS=(Resolve-Path .cache/v11-dev-ca.crt).Path`，再运行 Node 命令。浏览器如需真实管理交互，须在受控开发浏览器信任此公开 CA；本工具不会修改系统证书信任库。不要使用 `-k`、`InsecureSkipVerify` 或关闭 Node TLS 校验。上述 verify 需先有验收脚本的本地测试会话；普通日常 API 调用见 [API 说明](V1.1-API-USAGE.md)。

回环端口可用 `V11_DEV_PORT`、`V11_DEV_HTTPS_PORT` 调整；更改 HTTPS 端口也同步改变精确认证 origin。公开站内容中的 origin 始终固定 `https://xiaoworks.com`。

## 管理界面开发与路由

管理应用位于 `admin/`，拥有独立的 package/lock、TypeScript、ESLint、Vite 配置和测试。它不加入访客 Nuxt bundle，也不使用公开站路由兜底处理管理 API。

| 本地 HTTPS 路径     | 页面                                     |
| ------------------- | ---------------------------------------- |
| `/admin/`           | 工作区概览；草稿统计与公开状态分别显示   |
| `/admin/login`      | 管理员登录                               |
| `/admin/projects`   | 项目新增、编辑、归档、恢复与排序         |
| `/admin/categories` | 分类维护与排序                           |
| `/admin/media`      | 图片上传、元数据、私有预览与引用保护     |
| `/admin/profile`    | 品牌、个人介绍、技术能力与公开联系方式   |
| `/admin/settings`   | 网站文案、逐页 SEO 和分享图片草稿        |
| `/admin/publishing` | 发布门槛、全站差异、私有预览、任务与历史 |
| `/admin/account`    | 修改密码；成功后所有旧会话失效           |

网关仅对登记的管理页面返回 SPA shell，支持这些路径刷新及浏览器返回；未知管理路径、缺失的管理 JS/CSS 返回 404，不能伪装成成功 HTML。`/admin` 跳转到 `/admin/`。HTTP 可以取得管理静态界面，但真实认证和管理 API 始终要求同源可信 HTTPS。

在仓库根目录安装与检查独立应用：

```bash
npm --prefix admin ci --ignore-scripts
npm run admin:check
npm --prefix admin run format:check
npm run admin:test
npm run admin:build
```

`admin:check` 包含管理 ESLint、TypeScript 和单元测试；`admin:test` 是单测独立入口，不是浏览器验收。构建输出 `admin/dist/`，不生成源码映射。`admin/Dockerfile` 将该产物放入 gateway 的 `/srv/admin`；只更新 UI 时可保留现有 API 和全部数据卷，先构建并验证 gateway，再替换本站开发 gateway：

```bash
docker compose -f compose.admin-dev.yaml build gateway
docker compose -f compose.admin-dev.yaml up -d --no-build --no-deps --force-recreate --wait gateway
```

`npm --prefix admin run dev` 仅启动 `127.0.0.1:3211` 的 Vite 界面服务，没有认证 API 代理。它不能用于证明 Secure Cookie、Origin、TLS 或管理写操作已通过。该端口也可能被专用 E2E 环境占用，启动前检查，不停止其他任务的容器。

登录时获取一次性 challenge；会话 Cookie 为 HttpOnly/Secure，CSRF 和当前草稿只留在内存。localStorage 只保存 `xiaowork-admin-theme` 主题偏好。页面与静态管理资源设置 `no-store`、`noindex`，CSP 仅允许同源脚本/样式，不使用 `unsafe-inline` 或 `unsafe-eval`。主题初始化是外置脚本，不保存凭据。

表单具备未保存离开保护、409 保留输入与显式比较/重试、401 重新登录遮罩。恢复登录后核对工作区版本，不静默覆盖本页输入。P6-C 配置中预览、发布和历史恢复入口仍禁用并标注 P6-D；P6-D 需使用下文的独立配置及显式开关。私有素材预览不是公网图片地址。使用方法见 [中文管理操作说明](V1.1-ADMIN-USAGE.md)，实际浏览器覆盖与结果以对应阶段交付证据为准。

## 管理员与数据导入

首次创建单管理员使用真实交互 TTY，无回显输入两遍密码，不接受密码参数、环境变量、管道或默认密码：

```bash
docker compose -f compose.admin-dev.yaml exec -it api /homepage-api init-admin
# 输入用户名；按隐藏提示输入自选密码，12～128 Unicode 字符
# 明确执行一次性导入，经校验的 V1.0 资料只进入私有草稿
docker compose -f compose.admin-dev.yaml exec -T api /homepage-api import-v1
# 忘记本地测试密码时通过受控离线 TTY 重置，会撤销全部会话和 challenge
docker compose -f compose.admin-dev.yaml exec -it api /homepage-api reset-admin
```

重复初始化拒绝覆盖；重复导入返回首次来源记录，不覆盖任何编辑。种子包含 Blog/Nav/ERP 原 ID、顺序、精选、空技术栈和资料待确认状态，以及原分类、品牌与介绍，不将占位截图当真实截图。源 SHA、manifest 和 payload 哈希随导入记录。重新导出：`node scripts/export-admin-seed.mjs <完整已审SHA>`，只执行固定仓库模块、逐文件核对 Git 原文；Go API 不运行 TS/JS、Git 或任意命令。详见[迁移说明](V1.1-DATA-MIGRATIONS.md)。

## 自动验收

```bash
# 不含认证的管理静态路由与 HTTP 降级保护
node scripts/admin-dev-smoke.mjs http://127.0.0.1:3210
npm run smoke -- http://127.0.0.1:3210 https://xiaoworks.com --static-headers
# 仅对尚无管理员的本机隔离库执行：进程内随机密码，经 Docker 分配的真实 TTY 输入
# 不接受外部密码，不打印密码；仅支持已核验的本机 Docker Desktop pipe
node scripts/admin-api-smoke.mjs initialize-test
docker compose -f compose.admin-dev.yaml exec -T api /homepage-api import-v1
node scripts/admin-api-smoke.mjs verify
# 后续在保留卷的容器替换和再次导入后再运行 verify，核验原会话/草稿/图片哈希
```

自动初始化测试账户会占用本地的单管理员名额，已有账户时拒绝；它不能替代日常自选密码初始化。随机密码不保存，验收会话仅写入被 Git 忽略的 `.cache/p6b-local-session.json`，视同敏感测试文件，不上传、截图或打印。该会话仍受 30 分钟空闲/12 小时绝对过期限制，过期后按正常 TTY 重置并登录，不放宽认证配置。运行 Node 验收前需要上节的 `NODE_EXTRA_CA_CERTS`。

## P6-C 专用浏览器验收环境

仓库根目录的 `npm run admin:e2e` 调用 `scripts/admin-browser-test.mjs`，连接真实 Go/SQLite 服务，不把管理接口替换为成功响应。它使用专用 Compose 项目 `xiaowork-homepage-v11-p6c-e2e`、独立命名卷及 `192.168.248.0/28` control 网络，HTTP/HTTPS 分别只绑定 `127.0.0.1:3211`、`127.0.0.1:3444`，认证 origin 精确为 `https://localhost:3444`。浏览器自动化 WebSocket 另临时映射 `127.0.0.1:9323`，不能公开。它不使用或重置日常 `xiaowork-homepage-v11-dev` 数据库。先确认这些端口和子网空闲，关闭自己启动的 Vite 3211 服务；不要停止其他项目。

当前脚本适用于本机 Docker Desktop Linux Engine，校验 Windows 本机命名管道及专属 Compose 归属。浏览器在专用 Linux sidecar 中运行，不要求修改宿主 Windows 的 Root 信任库，也不采用关闭 HTTPS 校验的启动参数。独立管理依赖须已安装，运行所需 API、frontend、gateway 镜像应先完成本地构建与检查；脚本启动容器使用 `--no-build`，不会替你拉取未验证版本。还需从当前后端测试镜像离线编译会话过期夹具，以及准备固定版本 Playwright 浏览器测试镜像：

```bash
docker compose -f compose.admin-dev.yaml build
docker build --target build --file backend/Dockerfile --tag xiaowork-homepage-api:p6b-test .
docker build --file scripts/fixtures/expiry.Dockerfile --tag xiaowork-homepage-session-fixture:p6c-test scripts/fixtures
docker build --file scripts/fixtures/browser.Dockerfile --tag xiaowork-homepage-browser:p6c-test scripts/fixtures
npm run admin:e2e
```

脚本在忽略目录 `.cache/p6c-browser/` 生成专用 override，并从该项目 api-init 只导出公开 `ca.crt`，核验它是当前项目的有效 CA。浏览器 sidecar 只读挂载这份确切公开 CA、测试依赖和浏览器启动脚本，没有 Docker socket、数据库、会话秘密或上传卷。CA 信任仅加入该容器 `/tmp` 的独立 NSS 存储；脚本区分无信任和受信任浏览器，始终使用 `ignoreHTTPSErrors=false`，不使用 `-k` 或忽略证书错误开关。此前尝试宿主 Windows 信任接口出现超时的路径未作为最终方案，相关结果不能作为浏览器通过证据。

sidecar 使用非 root 用户、只读根、drop ALL、no-new-privileges 及临时 `/tmp`，与专用 gateway 共享网络命名空间，使浏览器通过同一个 `https://localhost:3444` origin 访问服务。结束时 `finally` 按确切测试归属标签删除 sidecar，其临时 NSS 存储随容器移除；不写宿主或生产的信任库。进程被强制终止时需核对并清理这个确切 sidecar，不能批量删除容器。

该环境用真实 Docker PTY 初始化或重置**专用测试管理员**，随机密码仅在进程内存在，不接受外部密码参数或文件。脚本会编辑测试内容、改密、重建专用 API/gateway，并用只挂载专用 DB 卷的夹具使某个测试会话过期。夹具为预编译的非 root 程序，运行时网络为 none、根文件系统只读，先检查卷的专属项目标签；不在 API 容器中临时编译或执行任意命令。这些操作仅用于专用验收卷，不能改为日常开发库或生产库。浏览器失败记录、脱敏请求结果及截图写入 `docs/evidence/`；不得额外保存 Cookie、CSRF、storageState、真实密码或私钥。

执行方法不等于验收通过；本阶段的实际覆盖、失败与修复以 P6-C 交付及脱敏浏览器报告为准。脚本完成后关闭浏览器并删除 sidecar，不自动删除 API/gateway 容器及持久卷。9323 的宿主映射属于专用 gateway，不能仅凭删除 sidecar 就宣称宿主转发层无监听；验收后停止专用项目并检查端口，或按该项目的明确配置移除自动化映射。只对专用测试项目执行保留卷的停止命令：

```bash
docker compose -p xiaowork-homepage-v11-p6c-e2e -f compose.admin-dev.yaml -f .cache/p6c-browser/compose.override.yaml down
```

保留日常开发环境与其他项目，不运行 `down -v` 或全局 prune。

## P6-D 独立本地发布环境

`compose.admin-publish.yaml` 是本地验收配置，不是生产部署 override。默认项目名 `xiaowork-homepage-v11-p6d-dev`，独立于 P6-C 的数据卷；gateway 仅绑定 `127.0.0.1:3212` 和 `127.0.0.1:3445`，认证 origin 精确为 `https://localhost:3445`，control 子网为 `192.168.249.0/28`。启动前检查这两个端口、子网和项目归属；不能停止其他项目或删除已有网络来解决冲突。

默认 `V11_LOCAL_PUBLISH=0`，且 worker 位于 `publisher` profile：仅启动普通服务不会获得发布能力。只有操作者明确设置 `V11_LOCAL_PUBLISH=1` 并启用该 profile，API 才接受本地发布任务；服务端还限制本地 origin、固定核验目标、完整源码 SHA 和 builder 身份，不支持把开关用于正式域名。环境变量不包含密码，勿将真实凭据放入 `.env` 或命令。

构建时必须使用已经审查的完整源码 SHA，工作区内容应与该源码一致；不能把任意未核验代码标记为已审版本。以下 Bash 步骤在仓库根目录执行，构建先保持发布关闭：

```bash
export V11_SOURCE_REVISION="$(git rev-parse HEAD)"
export V11_LOCAL_PUBLISH=0
docker compose --profile publisher -f compose.admin-publish.yaml config --quiet
docker compose --profile publisher -f compose.admin-publish.yaml build
# 构建后锁定实际 worker 镜像身份，供 API 与 worker 对账；重建镜像后重新读取
export V11_BUILDER_ID="$(docker image inspect --format '{{.Id}}' xiaowork-homepage-worker:p6d-dev)"
docker compose -f compose.admin-publish.yaml up -d --no-build --wait --wait-timeout 120
docker compose -f compose.admin-publish.yaml exec -it api /homepage-api init-admin
docker compose -f compose.admin-publish.yaml exec -T api /homepage-api import-v1
# 核对本地环境和资料后，显式启动发布能力
export V11_LOCAL_PUBLISH=1
docker compose --profile publisher -f compose.admin-publish.yaml up -d --no-build --wait --wait-timeout 120
docker compose --profile publisher -f compose.admin-publish.yaml ps -a
```

PowerShell 使用 `$env:V11_SOURCE_REVISION=(git rev-parse HEAD)`、`$env:V11_LOCAL_PUBLISH='0'`，构建后用 `$env:V11_BUILDER_ID=(docker image inspect --format '{{.Id}}' xiaowork-homepage-worker:p6d-dev)`；明确启用时改为 `$env:V11_LOCAL_PUBLISH='1'`。这些变量只用于当前本地终端，不写入仓库。初始化账户遵循前文真实 TTY 规则；重复导入不覆盖已编辑草稿。

访问 `https://localhost:3445/admin/` 前，从此项目 api-init 导出该项目自己的公开 CA，按前文方式核实和建立受控信任；P6-C 的 CA 不可替代。`http://127.0.0.1:3212` 用于查看本地访客站，HTTP 管理认证仍拒绝降级。在首次本地发布之前，访客请求回退到原 V1.0 静态前台。

### 使用流程与安全边界

在管理页保存内容仍只修改草稿。进入「发布、预览与历史」，读取当前 `ws-*` revision、活动版本与全站差异。私有预览不改变活动指针，完成后才出现受认证入口；HTML、JS、CSS、图片都经同源登录验证，设置 `no-store` 和禁止索引。当前预览 TTL 为构建完成后 24 小时，退出、会话过期、预览到期分别导致访问被拒绝。预览目录不能直接提升为正式产物。

全站发布和恢复前需要当前密码短时再认证，明确勾选完整范围。请求使用稳定幂等键、`If-Match` 草稿 revision，以及确认时的 `reviewedActiveReleaseId`（首次为 null）。活动版本或草稿已改变时返回 409，UI 读取最新状态并清除旧确认；不会自动用新版本重试。202 只表示任务接收，成功必须经过产物清单/哈希和独立 HTTP 核验，且实际活动版本一致。

worker 从镜像内已经安装的依赖和固定源码执行 Nuxt 静态生成，运行时网络为 none，不挂载 Docker socket、SSH 或生产配置。草稿经白名单公开投影后冻结为快照；敏感管理字段不进入公开构建。worker 对发布卷有写权限，API/静态服务只读；媒体读取限于经确认的固定派生文件。API/worker 通过专用卷中的 Unix socket 通信，不公开 worker HTTP 控制端口。

产物、清单、激活意图和回执保存在 `admin-publications` 专用卷，冻结快照及任务记录由专用数据库持久化。正式资源使用 `/_releases/rel_*/` 不可变路径，历史资源继续保留，使旧标签内部导航使用原版本；刷新读取新活动版本。恢复只切换已经验证且仍保留的静态版本，不重建历史内容、不覆盖当前草稿、账户或数据库。

切换结果不明确、worker 租约中断或对账不一致时，任务停留在待恢复核对状态，阻止新发布。重启后依据持久化意图、回执、当前指针与实际 HTTP 结果对账，不能证明安全时保持冻结。不要强改 `current`、删任务行、修改产物或删除卷解锁；保存本站脱敏任务 ID 和限量日志后排查。完整灾难恢复与多服务升级回滚仍由 P6-E 验收。

```bash
# 已验证镜像的本地保卷容器替换；会暂时中断这个独立本地环境
docker compose --profile publisher -f compose.admin-publish.yaml up -d --no-build --force-recreate --wait api worker publication-static gateway
docker compose --profile publisher -f compose.admin-publish.yaml logs --tail 50 api worker publication-static gateway
# 仅停止这个本地项目，保留账户、草稿、图片和发布卷
docker compose --profile publisher -f compose.admin-publish.yaml down
```

### P6-D 专用浏览器验收

`node scripts/publishing-browser-test.mjs` 使用专属项目 `xiaowork-homepage-v11-p6d-e2e`，不使用日常开发卷。它与上述 P6-D 日常配置使用相同的回环 3212/3445 和 control 子网，因此两者不能同时启动；先核实占用属于自己的环境，再按确切项目名保卷停止。9323 仅为临时浏览器自动化回环入口，禁止公开。

脚本要求已验证的 `p6d-dev` API、worker、gateway、legacy frontend 镜像，以及前文 P6-C 的专用浏览器/会话过期夹具镜像。它检查本机 Docker Desktop Linux Engine，从实际 worker 镜像读取源码 label 与镜像 ID；显式为专属测试环境启用本地发布，不从环境或文件接收测试密码。随机账户密码经真实 Docker TTY 初始化/重置，仅留在进程内存。CA 信任仅存在临时浏览器 sidecar 中，始终保持 TLS 验证。

脚本覆盖真实 UI 登录、预览、发布 A/B、旧 A 标签导航及版本资源、刷新 B、恢复 A 并保留草稿 B；逐项检查匿名/退出/Session 到期访问预览资源被拒绝。旧资源通过实际 `cache:no-store` 请求和 SHA-256 对比，保留正常 Nuxt 预取。随后保卷重建 API/worker/静态服务/gateway，核对原会话、草稿、活动版本、历史和预览资源，并检查发布页五宽度双主题。Session 到期验证不等于预览 TTL 到期验证，后者由 API 测试另行覆盖。

证据写入 `docs/evidence/P6D-browser.json` 与对应截图，只记录 HTTP 方法、路径、状态、资源哈希和检查结果，不保存密码、Cookie、CSRF、请求体、storageState 或 trace。上述是脚本覆盖目标，实际通过/失败/未运行以 P6-D 交付和报告为准。

脚本结束仅移除临时浏览器，不自动删除持久卷。验收后使用同一终端中的已核对变量，停止确切测试项目并检查回环入口；不要停止日常项目：

```bash
docker compose --profile publisher -p xiaowork-homepage-v11-p6d-e2e -f compose.admin-publish.yaml -f .cache/p6d-browser/compose.override.yaml down
```

禁止 `down -v` 和全局 prune。管理账户、私有图片与发布产物均不因本次本地验收被部署到生产。

## P6-C 容器边界与持久化

Compose 项目仍为 `xiaowork-homepage-v11-dev`。只有 gateway 绑定 `127.0.0.1:3210/3443`；API 无宿主端口，仅 control 私有网络，可信代理仅 gateway `.2/32`。网关覆盖 X-Forwarded-Proto/For，客户端不能用伪造头把 HTTP 变成可信 HTTPS。frontend 仍在原 isolated 网络。没有 Docker socket、SSH、生产配置或发布目录挂入 API。

DB、uploads、secrets、authority、tls 分别在本项目命名卷。API/gateway 为 UID10001、只读根、drop ALL、no-new-privileges、临时目录和日志轮转。上传卷只保存重新编码后的私有派生图片，草稿/快照引用阻止删除；无物理 GC。数据库外键/WAL/synchronous FULL/参数化 SQL/单连接事务及追加迁移生效。001 保持原文，schema2 不做降级。

```bash
docker compose -f compose.admin-dev.yaml logs --tail 50 api api-init gateway
# 保留卷替换 API；gateway 重新创建以刷新容器 DNS 解析
# 已经 build 通过后使用 --no-build，避免误拉未验证镜像
docker compose -f compose.admin-dev.yaml up -d --no-build --force-recreate --wait api gateway
# 仅停止本环境，保留全部卷
docker compose -f compose.admin-dev.yaml down
```

禁止 `down -v`、prune、复制运行中的主 SQLite 文件当完整备份。P6-B 原地升级前停本项目 API，确认连接关闭/WAL checkpoint 后保存本地备份；P6-E 再完成可重复备份恢复和多服务升级回滚演练。V1.0 `release.sh/deploy.sh/update.sh/rollback.sh` 没有改成 V1.1 部署器，不能用它们部署此功能分支或回滚 schema2。

## Go 开发与模块网络

Go 1.27.x（本轮1.27.3），纯 Go SQLite，无需 CGO。宿主方式需显式先 `migrate`、`init-secret`、TTY `init-admin`、`import-v1`，`serve` 不偷偷创建库/密钥/账户。直接 HTTP serve 的管理接口会拒绝，认证测试用受信任 HTTPS fixture 或上述 Compose 网关。

```bash
cd backend
go mod verify
go test -count=1 -v ./...
go vet ./...
go run golang.org/x/vuln/cmd/govulncheck@v1.9.0 -show verbose ./...
```

Docker构建默认官方 GOPROXY 和 Go 校验数据库。当前网络中官方代理返回了域名不匹配证书，首次构建按真实失败记录；随后用已有 P6-A 的 HTTPS 镜像参数成功，未关闭任何 TLS/sum 校验：

```bash
docker compose -f compose.admin-dev.yaml build --build-arg GOPROXY=https://goproxy.io api
docker compose -f compose.admin-dev.yaml up -d --no-build --wait --wait-timeout 120
```

P6-C 管理 UI 与 P6-D 静态发布使用各自独立的本地配置和阶段证据；完整备份恢复及正式 V1.1 部署准备仍待 P6-E。node-forge 等上游风险是否修复以当前实际依赖审计、兼容更新验证和阶段报告为准，不能沿用旧数字或把本地功能通过当作安全通过。管理前端或本地测试通过不意味着获得生产部署授权。
