# V1.1 独立开发环境（P6-A）

本环境只用于本机隔离开发。生产 V1.0 的 Compose、`.env`、`.deploy`、镜像和服务器数据不被复用或更新。P6-A 只提供 Go/SQLite 迁移与健康骨架；没有管理员、登录、CRUD、上传、预览和发布功能，`/admin/` 与所有管理 API 明确返回 503。

## Docker 一条命令启动

要求本机 Docker Linux Engine/Compose。先检查 3210 空闲，当前既有 3100 开发服务保持原样。

```bash
docker compose -f compose.admin-dev.yaml up -d --build --wait --wait-timeout 120
docker compose -f compose.admin-dev.yaml ps -a
```

不需要宿主安装 Go/Node，不需要密码或 Token。打开 `http://127.0.0.1:3210` 查看未改动的 V1.0 前台；`/admin/` 是明确的阶段说明。`/dev-health/api` 是本地诊断入口，返回 `p6a-scaffold`，不是未来公网契约。该路径不会加入生产配置。

若端口冲突，在当前 shell 设置 `V11_DEV_PORT` 为另一个空闲端口（PowerShell：`$env:V11_DEV_PORT='3215'`），不要修改原服务端口。Compose 端口地址固定为127.0.0.1，不提供公网绑定开关。

Compose 项目名是 `xiaowork-homepage-v11-dev`。api-init显式迁移空数据库后退出0，api/frontend/gateway各自健康；API和frontend无宿主端口，只有gateway绑定回环3210。API和frontend只接`internal:true`的isolated网络；gateway同时连接该网络和本项目独立edge网络，以提供Docker Desktop回环入口。不接生产或NPM共享网络，无Docker socket。DB和uploads分别在该项目独立命名卷内，容器替换不删除；本阶段uploads仅作为未来机制预留，没有上传接口。

```bash
docker compose -f compose.admin-dev.yaml exec -T api /homepage-api info
node scripts/admin-dev-smoke.mjs http://127.0.0.1:3210
npm run smoke -- http://127.0.0.1:3210 https://xiaoworks.com --static-headers
docker compose -f compose.admin-dev.yaml logs --tail 50 api api-init gateway
# 只停止本环境，保留数据卷
docker compose -f compose.admin-dev.yaml down
```

不要加 `-v`，不执行prune，不用现有`deploy.sh/release.sh`启动此环境。不把本文件当作已验证的V1.1生产升级脚本。

Go依赖默认来自官方代理，`go.sum`和默认Go校验数据库保持启用。若网络发生TLS证书不匹配，不能设GOINSECURE/关闭TLS或sum验证。可排查网络，或显式选择受信任的HTTPS模块镜像（本轮使用以下本地构建参数，仓库默认仍为官方）：

```bash
docker compose -f compose.admin-dev.yaml build --build-arg GOPROXY=https://goproxy.io
docker compose -f compose.admin-dev.yaml up -d --no-build --wait --wait-timeout 120
```

这个参数仅用于构建阶段下载公开依赖，不可填凭据。构建编译阶段`GOPROXY=off`，不会临时拉取未锁模块。生产选择和镜像digest在P6-E另审。

## 可选：宿主Go开发

需要Go1.27.x（本轮1.27.3），modernc SQLite驱动纯Go，不依赖宿主sqlite3或CGO。代码默认监听回环8081，先检查端口。数据库默认放在`backend/.data/v11-dev/`，已忽略。

```bash
cd backend
go mod download
go test -v ./...
go vet ./...
go run ./cmd/homepage-api migrate
go run ./cmd/homepage-api info
go run ./cmd/homepage-api serve
```

`migrate`仅接受空库或同版schema，未知数据库/更高版本拒绝；不创建默认账户，不导入假内容。`serve`缺库或schema不兼容时拒绝启动，不偷偷建库。`info`输出实际SQLite核心和schema。每个连接配置外键、5s busy timeout、WAL、synchronous FULL；核心版本门槛>=3.51.3。当前只有schema1的初始迁移，生产迁移锁、备份、兼容升级在P6-B/E实现。

## 后续实施要求

- 管理员初始化以后采用受控交互CLI（不从命令行明文密码、默认密码、前端配置或镜像环境读取），P6-A不存在这个命令。
- P6-C建立真实Vue管理应用前，不能把阶段说明页面标成“后台可用”。P6-B认证未验收时不开放业务接口。
- 不在本环境运行ERP真实数据、生产账户、私钥或数据库备份；只使用明确测试素材，生产迁移后续另授权。
- 启动/替换测试只操作本项目命名资源，保留卷并对持久化进行实际验证。发布worker、原子切换和备份恢复仍是P6-D/E验收项。
