# V1.1 本地静态发布、预览与内容恢复

P6-D 实现独立本地发布协议，P6-E 补充真实故障、容量、备份和运维验收。本说明不能用作已授权的生产部署步骤。生产管理 origin 不允许开启 `XIAOWORK_LOCAL_PUBLISH`；原 V1.0 镜像部署状态、服务器、OpenResty 和 Cloudflare 不在本阶段操作范围。

## 环境与身份

`compose.admin-publish.yaml` 是独立编排，不与 `compose.admin-dev.yaml` 的数据库、图片、会话或证书卷共享。默认项目 `xiaowork-homepage-v11-p6d-dev`，仅宿主回环 HTTP 3212 / HTTPS 3445；API、静态服务与 Worker 无宿主端口。专用浏览器验收使用另一个项目 `xiaowork-homepage-v11-p6d-e2e`。

源码经过检查并提交后，可在 Bash 环境执行：

```bash
bash scripts/publishing-dev.sh build
bash scripts/publishing-dev.sh status
```

脚本拒绝未提交的应用构建输入及远程 SSH Docker context。镜像内预装锁定依赖，构建阶段可以使用受信 Go 代理，TLS 与 go.sum 校验保持开启。脚本取得完整源码 SHA 和实际 Worker 镜像 `sha256:` ID；API 与 Worker 必须使用同一身份。不要用浮动 Git ref 或伪造 SHA 替代。

默认不开启发布 Worker。仅在隔离本地验收中显式启用：

```bash
V11_LOCAL_PUBLISH=1 bash scripts/publishing-dev.sh start
```

首次管理员由交互 TTY 初始化，不接受密码参数、环境变量或管道：

```bash
docker compose -f compose.admin-publish.yaml exec -it api /homepage-api init-admin
docker compose -f compose.admin-publish.yaml exec -T api /homepage-api import-v1
```

执行 Compose 命令时，需按脚本使用相同的 `V11_SOURCE_REVISION`、`V11_BUILDER_ID` 和本地开关。信任该专用环境的公开 CA 后访问 `https://localhost:3445/admin/publishing`；不要关闭浏览器、curl 或程序的证书验证。普通开发环境仍可保存草稿，发布能力保持关闭。

## 操作顺序

1. 在项目、分类、品牌及设置页面保存草稿。修改不会更新访客站。
2. 进入“发布与恢复”，重新读取草稿与发布状态，核对 revision 和新增、修改、隐藏、归档及品牌/分类/SEO 变更摘要。
3. “构建私有预览”冻结当前 revision，返回的是任务受理信息。预览完成后才出现入口；该入口及 HTML、图片、JS、CSS 均逐请求验证管理员会话，退出或到期后拒绝访问。
4. 发布前再次验证密码，并确认本次包含整个站点的全部草稿变化。发布重新生成正式路由产物，不能提升预览目录。按钮返回 202 只代表排队。
5. 等待真实任务状态。仅当不可变目录、current、激活凭据、SQLite 和静态 HTTP 响应对账完成，才显示当前版本已核验。
6. 恢复历史版本前再次验证密码，选择完整保留且兼容的成功版本并确认。只切换公开内容，不覆盖草稿、账号、SQLite schema、Git 或容器镜像。

遇到 409 保留表单并重新比较。网络中断、Worker 不可用、`reconciling` 或 `recovery_required` 时先查询同一个任务，不能通过更换幂等键盲目重试。结果不明会阻断后续任务；不要手动把数据库状态改成 succeeded，也不要手动改 current 绕过对账。

## 数据与资源保留

- SQLite、私有上传、发布根、会话秘密与本地证书均为独立持久卷。
- Worker 无网络、数据库、会话秘密、Docker socket 或部署凭据。固定程序只执行固定 Nuxt 构建命令，输入是封存的公开数据和已确认的重编码媒体。
- `publications/current` 指向一个完整不可变 release；HTML 不缓存，所有新 JS/CSS/图片/主题脚本按 release 版本路径保留。旧标签页继续使用旧快照，刷新才读取当前版本。
- `manifest.json`、快照、staging、激活记录和预览没有公开 Nginx 映射。上传原目录不公开。
- 默认不自动删除成功版本及其图片。预览过期后拒绝访问，磁盘清理由后续经过验证的保留政策处理；不能用全局 prune 或删卷清理。
- 当前恢复策略保守要求完全相同的源码 SHA、内容格式及 Worker 镜像 ID；代码升级后的跨构建器恢复会被拒绝，需要另行迁移/重建验收。
- `rollback.sh` 是 V1.0 镜像回滚，与后台内容恢复不是同一操作，不能共用状态目录。

## 停止与排障

```bash
bash scripts/publishing-dev.sh status
bash scripts/publishing-dev.sh stop
```

停止保留全部卷。日志只查看本项目服务，不输出 Cookie、CSRF、密码、完整私有配置或数据库内容。出现不确定激活状态时保留发布目录及任务记录，先核实 current / intent / receipt / manifest / HTTP，再执行受控恢复。不要删除数据库重新初始化，也不要覆盖历史产物。一致性备份、新空卷恢复与 V1.1 专用生命周期见 [备份恢复](V1.1-BACKUP-RESTORE.md) 和 [更新与回退](V1.1-RELEASE-OPERATIONS.md)。

实际通过和未通过的验证以 [P6-D 交付](deliveries/P6D-delivery.md) 与测试证据为准；实现存在不代表所有故障场景已经验收。

## P6-E 容量和人工恢复边界

图片原件最多10 MiB、multipart最多11 MiB，重编码后的单文件最多16 MiB，单快照公开媒体合计最多256 MiB；Worker、预览及独立HTTP校验使用同一份限制。上传前图片尺寸还需满足8192单边/2500万像素。超限重编码在登记成功前拒绝，不能通过修改后端配置绕过发布器限制。

发布页显示数据库、图片及发布目录的剩余空间和受限用量统计。余量少于512 MiB或2%、无法核实余量时，新任务和上传被拒绝；少于1 GiB或10%提前警告。固定构建器另检查至少256 MiB临时空间；Worker受CPU、内存、PID、tmpfs限制。此机制不是总配额或磁盘预留，仍可能被同机其他进程耗尽空间。

全站预览、发布和内容恢复共用一个未完成任务槽，不并发构建。成功历史、已引用图片、备份和故障现场均保留；目前不执行自动物理GC，操作者应定期查看用量并安排受控离线归档。

Worker/API断开或验证服务不可用后，可能需要重启本站Worker、等待真实120秒租约，再核对同一任务；不能声称全部故障都自动恢复。恢复失败或状态不明时保持 `reconciling/recovery_required`，禁止新任务。切换前崩溃可能遗留 `current.next.*`，维护备份会保守拒绝此额外链接；必须先人工核对和修复，不能直接删除现场或手改成功记录。

完整真实容器故障和未完成门槛见 [P6-E故障矩阵](P6E-FAULT-TESTS.md) 与 [P6-E交付](deliveries/P6E-delivery.md)。这些本地结果不代表已允许正式环境启用发布。

## 本地验收工具与证据

以下工具只用于本机独立测试数据，不接触生产。浏览器工具会创建专用环境、通过TTY初始化随机测试账户并信任专用公开CA；不会关闭TLS校验。需要本机Docker Desktop及已有的验收浏览器镜像。

```bash
npm run publishing:e2e
node scripts/publishing-http-evidence.mjs
node scripts/publishing-interruption-test.mjs
node scripts/publishing-docker-evidence.mjs <验收镜像记录的完整源码SHA>
```

正常浏览器工具实际构建预览、发布A/B、验证旧标签资源并恢复A，还验证保卷重建。HTTP工具仅请求回环3212，并校验页面、版本、SEO及全部公开资源。中断工具只在识别到确切任务的固定Nuxt进程后终止专用Worker，等实际可用性期限及120秒租约后核对原任务；它会保留测试容器和数据供排查，不应在正式环境执行。Docker工具只读取固定项目的非敏感权限/健康/挂载投影，并比较既有容器身份。

本轮 [正常浏览器](evidence/P6D-browser.json)、[HTTP/SEO](evidence/P6D-public-http-seo.json)、[真实中断](evidence/P6D-worker-interruption.json)、[Docker](evidence/P6D-docker.json) 均通过。中断仅覆盖真实构建阶段，不代表切换或结果写入瞬间的容器退出已验收。测试结束对确切项目执行不带`-v`的Compose停止，七卷保留，临时浏览器/9323入口撤除，见 [最终清理](evidence/P6D-e2e-cleanup.json)。不同测试轮次的版本以各自证据为准。
