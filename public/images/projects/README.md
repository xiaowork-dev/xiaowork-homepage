# 项目封面资源

每个项目使用独立目录：`blog/`、`nav/`、`erp/`。当前目录内 `placeholder.svg` 为 P2 已验收的原占位图副本，不是真实截图。旧的 `*-placeholder.svg` 保留兼容，不再由配置引用。

接入真实封面的步骤：

1. 取得本人确认可公开、无敏感信息的真实截图；ERP 只接受经过确认的演示画面。
2. 将压缩后的图片放入对应项目目录，建议约 960×600 或其他 16:10 比例，不含账号、令牌、客户和业务数据。
3. 在 `app/data/project-covers.ts` 更新该项目的 `cover`、`coverAlt` 和 `coverKind: 'screenshot'`。保留明确、准确的替代文本。推荐以 PNG/JPEG 作为兼容回退；有经过压缩的同画面变体时设置 `coverSources: { avif: '/images/projects/<slug>/cover-v1.avif', webp: '/images/projects/<slug>/cover-v1.webp' }`，没有的格式省略，不引用不存在文件。`picture` 由浏览器选择支持的格式；也可以直接将 WebP/AVIF 设置为 `cover`。
4. 分别在首页和项目页、深浅主题与手机布局验证。固定 960×600 宽高属性和 16:10 显示比例预留空间；不同比例会居中裁切，务必检查关键内容。首张封面优先加载，其余懒加载。加载失败时，卡片会回退到通用 `placeholder.svg` 并说明图片暂不可用；通用图也失效则保留相同比例的文字后备，不重复请求。
5. 用浏览器检查网络中 `currentSrc`、真实尺寸和文件大小。建议 960×600 截图以 150 KB 内作为压缩起点，根据文字可读性调整，不能以模糊截图换分数。现代格式的转换应在素材制作阶段离线完成，本站不增加图片服务或实时第三方依赖。
6. 图片缓存为一天。替换素材优先使用新文件名（如 `cover-v2.webp`）并更新配置；不要期望同名文件在所有客户端立即失效。旧文件在确认无引用后再移除。

截图与项目状态独立管理：有截图不代表已经上线。状态、技术栈与链接仍需分别确认。新增项目可以直接在 `projects.ts` 配置 `cover` / `coverAlt` / `coverKind`，或在封面注册表新增一项后展开引用，无需修改卡片组件。
